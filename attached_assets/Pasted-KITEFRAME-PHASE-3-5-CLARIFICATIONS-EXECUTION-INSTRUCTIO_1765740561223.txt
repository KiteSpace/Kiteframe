SECTION 1 — WORKFLOW INTENT: MAJOR EDIT DEFINITION
-------------------------------------------------------------

Definition:
A "major edit" is any change that alters the semantic meaning of a workflow.
Cosmetic or positional changes MUST NOT trigger intent invalidation.

MAJOR EDITS (trigger intent re-validation):
- Node added
- Node deleted
- Edge added
- Edge deleted
- Edge reconnected (source/target change)
- Node type changed (e.g. process → decision)
- Node label or content changed (text, form fields, logic description)
- Workflow split or merge (connected components change)

NON-MAJOR EDITS (DO NOT trigger intent):
- Node position changes
- Zoom / pan
- Styling or color changes
- Collapse / expand
- Selection changes
- Renaming workflow without content change

Implementation:
- Introduce workflowIntentHash
- Recompute hash only on MAJOR edits
- If workflowIntentHash !== storedIntentHash:
    → mark intent as stale
    → DO NOT force re-capture immediately
    → surface soft UI prompt when relevant actions occur

Intent capture occurs:
- Automatically on first workflow creation
- Prompted only after a MAJOR edit (never on minor edits)

-------------------------------------------------------------
SECTION 2 — REACTIVE PRD: STALENESS & REGENERATION RULES
-------------------------------------------------------------

Hard Rule:
PRDs MUST NEVER auto-regenerate.
All regeneration is explicitly user-initiated.

On workflow change:
- Compute semantic hash (existing system)
- If hash mismatch:
    → mark affected PRD sections as "stale"
    → show inline banner:
      "This section may be out of sync with the workflow"

Regeneration behavior:
- User clicks "Regenerate"
- Regenerate ONLY sections that:
    → do NOT have manualEditedAt set
- Preserve all manually edited sections
- If ALL sections are manually edited:
    → require explicit overwrite confirmation

Merge strategy:
- No diff/merge logic in Phase 3.5
- Regeneration is section-scoped, not document-wide
- Always save previous version as backup (already implemented)

SECTION 3 — CROSS-WORKFLOW ANALYSIS (PROJECT-LEVEL)
-------------------------------------------------------------

Surface location:
Project Tab → new subsection: "Insights"

Structure:
Project
 ├─ Overview
 ├─ Workflows
 ├─ Insights   (NEW)
 ├─ Notes
 └─ Links

Behavior:
- Read-only AI-generated analysis
- NO canvas mutation
- NO auto-generation of nodes
- NO blocking behavior

Insights include:
- Shared assumptions across workflows
- Conflicting goals or definitions
- Missing coverage between workflows
- Global risks (single points of failure, handoff gaps)

This is a PM review surface, not an editor.

-------------------------------------------------------------
SECTION 4 — WORKFLOW MATURITY SYSTEM
-------------------------------------------------------------

Maturity States:
- Draft
- Reviewed
- Stable

Key Rule:
"AI must not auto-execute on Draft workflows" means:

ALLOWED in Draft:
- AI explanations
- Clarifying questions
- Suggestions
- Insight chips
- PRD preview generation

BLOCKED in Draft:
- Auto workflow generation
- Applying changes to canvas
- Auto PRD regeneration
- "Fix this workflow" actions

Enforcement:
- Gate execution actions behind:
    workflow.maturity !== 'draft'
- UI badge:
    "Draft — AI suggestions only"
