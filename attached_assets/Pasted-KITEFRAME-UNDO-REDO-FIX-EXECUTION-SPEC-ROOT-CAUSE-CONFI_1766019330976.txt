KITEFRAME — UNDO / REDO FIX EXECUTION SPEC
(ROOT CAUSE CONFIRMED)

Status:
Root cause identified. Undo/redo failure is NOT due to mutation,
but due to incorrect activity comparison logic + debounced snapshot timing.

This document specifies the REQUIRED changes to fix undo/redo reliably.

==================================================
PROBLEM SUMMARY (CONFIRMED)
==================================================

Current logic incorrectly determines "no change" using ONLY array length checks:

workflow-editor.tsx (≈ line 3177–3188)

if (
  lastState &&
  lastState.nodes.length === currentNodes.length &&
  lastState.edges.length === currentEdges.length &&
  lastState.canvasObjects.length === currentCanvasObjects.length
) {
  console.log(`[ACTIVITY] ⏭️ SKIPPED (no change)`);
  return;
}

This breaks undo/redo for:
• Node movement
• Theme changes
• Label edits
• Property updates
• Reordering
• Any non-add/remove mutation

SECONDARY ISSUE:
saveToHistory is debounced (200ms), causing snapshots to capture POST-mutation state,
making "before" and "after" identical.

==================================================
REQUIRED FIXES (MANDATORY)
==================================================

--------------------------------------------------
FIX 1 — REPLACE LENGTH-ONLY COMPARISON
--------------------------------------------------

❌ REMOVE length-only equality logic entirely.

✅ Replace with ONE of the following (preferred order):

OPTION A (Preferred):
• Reference equality comparison
• Snapshot immutability enforced

Example:
if (
  lastState &&
  lastState.nodes === currentNodes &&
  lastState.edges === currentEdges &&
  lastState.canvasObjects === currentCanvasObjects
) {
  SKIP
}

OPTION B (Safe fallback):
• Deep structural comparison

Implement:
• fast-deep-equal OR
• structuredClone + JSON.stringify (MVP acceptable)

Example:
if (deepEqual(lastState, currentState)) SKIP

⚠️ Length checks alone are NOT acceptable.

--------------------------------------------------
FIX 2 — CAPTURE SNAPSHOT SYNCHRONOUSLY
--------------------------------------------------

Current behavior:
• saveToHistory is debounced by 200ms
• Mutation happens immediately
• Snapshot captures already-mutated state

❌ This invalidates undo.

✅ REQUIRED CHANGE:

• Capture snapshot synchronously BEFORE mutation
• Debounce ONLY the history PUSH, not snapshot creation

Example pattern:

const snapshot = captureCurrentState(); // synchronous
mutateState();
enqueueHistory(snapshot, label); // debounced OK

OR

Remove debounce entirely for saveToHistory
(debounce may remain for UI-only telemetry)

--------------------------------------------------
FIX 3 — DEFINE SNAPSHOT CONTENT EXPLICITLY
--------------------------------------------------

Snapshot MUST include:
• nodes (deep copy)
• edges (deep copy)
• canvasObjects (deep copy)
• viewport
• themes / styling
• workflow metadata

Snapshot MUST NOT:
• reference live mutable objects
• reuse arrays or object references

Use:
• structuredClone
• or explicit deep copy helpers

--------------------------------------------------
FIX 4 — ENSURE EVERY USER ACTION CREATES HISTORY
--------------------------------------------------

Explicitly verify undo coverage for:
• Add node
• Delete node
• Move node(s)
• Drag workflow
• Apply theme
• Add shape
• Delete shape
• Edit labels
• Auto-layout

Each user-visible change MUST:
• create exactly ONE undo step
• never log SKIPPED unless truly no-op

--------------------------------------------------
FIX 5 — ADD REGRESSION GUARD
--------------------------------------------------

Add assertion:

if (label !== 'NO_OP' && historyNotUpdated) {
  console.warn('Undo regression detected:', label);
}

Add automated test coverage:
• Theme change → undo restores previous theme
• Drag node → undo restores position
• Label edit → undo restores text
