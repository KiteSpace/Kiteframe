PHASE 6.8 — SEMANTIC TERMINAL INFERENCE (TEST FLIGHT FALSE-POSITIVE FIX)
MODE: READ-ONLY, FEATURE-FLAGGED, NO GRAPH MUTATIONS
GOAL: Reduce “dead-end-node” false positives for semantically terminal leaf nodes
      (e.g., “Notify user”, “Setup complete”, “Dashboard created”) WITHOUT changing
      the core workflow model (output nodes remain first-class).

────────────────────────────────────────────────────────────
LOCKED CONSTRAINTS (DO NOT VIOLATE)
────────────────────────────────────────────────────────────
1) NO GRAPH MUTATION
   - Do NOT change node.type
   - Do NOT add/remove nodes/edges
   - Do NOT “auto-fix” dead ends
   - This is diagnostics-only suppression / reclassification

2) OUTPUT NODES REMAIN GOLD STANDARD
   - Explicit node.type === 'output'|'end' is always considered terminal
   - Semantic inference only applies to leaf nodes that are NOT typed output/end

3) EXPLAINABILITY REQUIRED
   - Every suppression must record “why” (reasons + confidence)
   - Must be visible in diagnostics output + WhyInspector + audit export

4) SAFE BY DEFAULT
   - Only suppress warnings at HIGH confidence
   - Medium confidence should NOT suppress; instead emit a softer “suggestion”
   - Low confidence behaves like today (dead-end warning)

5) FEATURE FLAGGED
   - Must be controlled via VITE_ENABLE_SEMANTIC_TERMINAL_INFERENCE
   - Default ON for Beta, OFF for Production until validated

────────────────────────────────────────────────────────────
DELIVERABLE OVERVIEW
────────────────────────────────────────────────────────────
A) detectTerminalIntent(node, incomingEdges, outgoingEdges, graph) → TerminalIntentSignal
B) DiagnosticsEngine uses this signal to:
   - suppress dead-end warnings for HIGH-confidence semantic terminals
   - emit “semantic-terminal” informational issue for visibility
C) DecisionSnapshot stores semantic terminal signals
D) WhyInspector and Audit Export surface the signals

TASK 2 — IMPLEMENT TERMINAL INTENT DETECTOR (DETERMINISTIC, NO AI)
────────────────────────────────────────────────────────────
Create file:
  client/src/ai/semantics/detectTerminalIntent.ts

Add types:
  export type TerminalConfidence = 'high' | 'medium' | 'low';

  export interface TerminalIntentSignal {
    isLikelyTerminal: boolean;
    confidence: TerminalConfidence;
    reasons: string[];          // human-readable, short
    matchedRules: string[];     // stable IDs for audit/debug
  }

Implement:
  export function detectTerminalIntent(args: {
    node: Node;
    incomingEdges: Edge[];
    outgoingEdges: Edge[];
    nodesById: Map<string, Node>;
    edgesById?: Map<string, Edge>;
  }): TerminalIntentSignal

RULES (deterministic + explicit):
A) Only evaluate if:
   - outgoingEdges.length === 0
   - incomingEdges.length > 0
   - node.type NOT in ['output','end']

B) Compute text fields:
   - label = node.data?.label ?? node.data?.title ?? ''
   - description = node.data?.description ?? node.data?.text ?? ''
   - combined = `${label} ${description}`.toLowerCase()

C) HIGH confidence triggers (any one is sufficient):
   1) Completion keywords:
      - includes any of:
        ["complete","completed","done","finished","finalized","success","successful",
         "created","submitted","sent","notified","confirmed","approved","rejected",
         "account created","setup complete","dashboard created","request processed"]
      matchedRules: "TERM_HIGH_KEYWORD"
   2) Explicit end-of-flow phrases:
      - includes any of:
        ["flow ends here","end of flow","no further action","process ends"]
      matchedRules: "TERM_HIGH_EXPLICIT_END"
   3) Decision-branch terminal context:
      - if the incoming edge(s) from a condition node has a label suggesting final outcome:
        edge.label includes any of ["approved","rejected","complete","completed","success","failed","denied"]
      matchedRules: "TERM_HIGH_DECISION_OUTCOME"

D) MEDIUM confidence triggers (do NOT suppress warnings; create soft issue):
   - Notification-ish actions without explicit completion:
     keywords like ["notify","inform","email user","send message","show confirmation"]
     matchedRules: "TERM_MED_NOTIFY"
   - Administrative closure actions:
     ["archive","log","record","store","audit"]
     matchedRules: "TERM_MED_ADMIN"

E) LOW confidence default:
   isLikelyTerminal=false, confidence='low'

OUTPUT:
- If HIGH triggers matched → {isLikelyTerminal:true, confidence:'high', reasons:[...], matchedRules:[...]}
- If only MEDIUM matched → {isLikelyTerminal:true, confidence:'medium', ...}
- Else → {isLikelyTerminal:false, confidence:'low', ...}

IMPORTANT:
- Keep reasons short and user-facing
- Keep matchedRules stable and machine-readable
- No regex required initially; use simple includes()
- Add unit tests in Task 7

TASK 4 — INTEGRATE INTO DiagnosticsEngine.detectDeadEndNodes()
────────────────────────────────────────────────────────────
File: client/src/lib/kiteframe/utils/diagnostics/DiagnosticsEngine.ts

Locate detectDeadEndNodes()

Current behavior:
- For each node:
  if outgoing.length === 0 && incoming.length > 0 && !isTerminalNode(node)
    emit dead-end-node issue

New behavior (flagged):
1) Build nodesById map once per run
2) When a node qualifies as dead-end candidate:
   - If flag OFF → existing behavior unchanged
   - If flag ON → call detectTerminalIntent()

Branching:
A) If detectTerminalIntent returns:
   isLikelyTerminal=true AND confidence='high'
   THEN:
   - DO NOT emit dead-end-node issue for this node
   - Emit a 'semantic-terminal' issue instead
     message example:
       title: "Semantically terminal step"
       description: "This step appears to be an acceptable endpoint even though it is not typed as an output."
     Include semanticTerminal payload

B) If isLikelyTerminal=true AND confidence='medium'
   THEN:
   - Keep existing dead-end-node issue (do not suppress)
   - ALSO emit a 'semantic-terminal' issue as “soft suggestion”
     (Use copy that suggests converting to output node if desired)

C) Else:
   - Keep existing dead-end-node issue

IMPORTANT:
- Do not change detectMissingEndState() yet in Phase 6.8 (keep scope minimal)
- Only modify dead-end detection to reduce false positives
