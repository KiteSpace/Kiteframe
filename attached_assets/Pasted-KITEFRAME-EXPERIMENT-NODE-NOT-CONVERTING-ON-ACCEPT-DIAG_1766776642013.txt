KITEFRAME — EXPERIMENT NODE NOT CONVERTING ON ACCEPT
DIAGNOSIS + FIX PLAN (BASED ON REPLIT ANSWERS)

SUMMARY OF WHAT WE NOW KNOW
- Conversion is intended to happen ONLY on “Accept”.
- Conversion code is in workflow-editor.tsx: onExperimentAdoptBranch (lines ~10311–10408).
- Conversion is “immutable” (map -> new object).
- There is an early-return if generatedNodeIds/generatedEdgeIds are empty.
- The converted node’s displayed content depends on:
  userPrompt || selectedOptionDescription || selectedOptionLabel || '' (empty string fallback)
- A “normalizer” or follow-on effect may be overwriting the converted node.

1) CONFIRM THE ACCEPT EVENT IS FIRING (MOST COMMON)
Problem pattern:
- User clicks “Accept” visually, but onExperimentAdoptBranch never runs.

Replit: Please confirm all of the following with code refs:
1.1 Where is ExperimentBranchHeader rendered?
- File + component name
- How does it receive the callbacks?

1.2 Confirm the callback chain:
ExperimentBranchHeader onAccept ->
  calls props.onAccept(experimentId OR originNodeId?) ->
  workflow-editor.tsx onExperimentAdoptBranch(...) invoked

1.3 Add a hard log at the FIRST line of onExperimentAdoptBranch:

If this log does not show every time you click Accept:
- The problem is prop drilling or mismatched identifiers (originNodeId vs experimentId).

Fix expectation:
- ExperimentBranchHeader should call adopt with a stable identifier that workflow-editor can map to the origin experiment node:
  Prefer: originNodeId OR experimentId, but the entire pipeline must be consistent.

2) CHECK THE EARLY RETURN GATE (LIKELY)
Replit noted an early return at ~line 10320 if generated ids are empty.

2.1 Add log right before the early return:
console.log('[EXPERIMENT] Adopt precheck', {
  originNodeId,
  genNodes: data.generatedNodeIds?.length,
  genEdges: data.generatedEdgeIds?.length,
  hasGeneratedBranch: data.hasGeneratedBranch
});

2.2 If genNodes/genEdges are empty:
Root cause is NOT conversion; it’s the generation phase not persisting generatedNodeIds/generatedEdgeIds onto the origin node reliably.

Fix:
- In the generate branch handler, ensure the origin experiment node is updated in the SAME setNodes call that inserts generated nodes, so generated ids cannot be lost due to stale state.
- Do not rely on component-local state for ids. Store ids in node.data on the origin node.

Expected result:
- After clicking Generate, the origin experiment node in React state MUST contain:
  data.generatedNodeIds (non-empty)
  data.generatedEdgeIds (non-empty)
  data.hasGeneratedBranch === true

3) CONTENT LOOKS “MISSING” EVEN THOUGH CONVERSION HAPPENED
Replit: conversion sets data.description = experimentContent computed as:
userPrompt || selectedOptionDescription || selectedOptionLabel || ''

If those are undefined, the converted node will look blank-ish even though it converted correctly.

3.1 Confirm that when a user selects a suggested option:
- selectedOptionLabel is always set
- selectedOptionDescription is set (optional but preferred)

3.2 Confirm Prompt mode always writes userPrompt (trimmed, non-empty)

Fix (strongly recommended):
- Add a hard assertion before conversion:
if (!experimentContent.trim()) {
  toast.error('Select an option or enter a prompt before accepting.');
  return;
}

And ensure Option selection writes at least label.

4) NORMALIZER OR EFFECT IS REVERSING CONVERSION (PLAUSIBLE)
Replit flagged experimentNormalizer as a risk.

4.1 Identify every place experimentNormalizer runs:
- file(s) and exact triggers (useEffect? on nodes change? on load?)
- Does it assume type === 'experiment' for nodes that have meta.experiment?

4.2 Add a log AFTER accept conversion, and then another log 1 tick later:
requestAnimationFrame(() => {
  const node = nodes.find(n => n.id === originNodeId);
  console.log('[EXPERIMENT] Post-RAF node snapshot', node);

If you see type becomes 'process' then later becomes 'experiment' again:
- A follow-up normalizer/effect is overwriting state with stale data.

Fix:
- Normalizer must be idempotent and must not “restore” experiment nodes once accepted.
- Rule: if node.meta.experiment?.acceptedAt exists, do not normalize it back into Experiment shape.

--------------------------------------------
5) IDENTIFIER MISMATCH: experimentId VS originNodeId (HIGH RISK)
Replit’s mutation payload uses:
meta: { experimentId, ... }

But the actual node id is distinct (originNodeId). Many bugs come from mixing these.

Replit: Confirm:
- What identifier does ExperimentBranchHeader store and pass on Accept?
  - experimentId OR origin node id?

- What does workflow-editor.tsx expect as its argument?
  - If it expects origin node id but receives experimentId, it won’t find the node to convert.

Fix:
- Standardize:
  - originNodeId = the actual node.id of the experiment node
  - experimentId = stable grouping id for generated branch nodes/edges

Adopt handler should accept originNodeId, and read experimentId from node.meta or node.data.
