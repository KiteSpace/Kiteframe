Clarification: the two specific implementation bugs to fix

Thanks — you’re correct that the AI unification and Experiment/Explore refactor are already merged. The task file is not asking for changes to those areas.

There are two concrete, observable implementation bugs that remain. Both are in graph lifecycle and rendering, not AI prompts or Experiment/Explore definitions.

Bug 1 — Preview vs Commit Topology Is Incorrect

Symptom (observable in UI):

When an Experiment or Explore generates speculative branches:

The generated branch nodes are connected directly to the origin/context node

They should instead be connected to the Experiment/Explore node during preview

As a result:

The Experiment/Explore node does not function as the temporary parent

Preview mutations appear to affect the “real” workflow topology

Accept/Create has no clean re-parenting step, because mutation already happened

Expected behavior:

Preview state

origin → Experiment/Explore → proposed branch subtree

On Accept/Create

Remove the Experiment/Explore node

Reattach the proposed branch subtree to the origin node

Persist the change once

What’s wrong in implementation terms:

Preview graph mutations are being applied as if they were committed

There is no isolation between preview topology and committed topology

Preview edges/nodes are being treated as first-class graph state

Scope of fix:

Introduce explicit preview graph state

Ensure preview branches attach to the Experiment/Explore node

Ensure Accept/Create performs re-parenting and persistence

Do not touch AI generation logic, prompts, or Experiment/Explore definitions

Bug 2 — AI-Generated Node Content Is Not Plumbed Correctly

Symptom (observable in UI):

AI-generated branch nodes show:

Header populated (often verbose or step-like)

Body text showing placeholder: “Double click to edit text.”

This occurs even though AI generation completed successfully

Expected behavior:

For AI-generated nodes:

Header = concise step title (short label)

Body = expanded description of what happens at that step

Body text should never be empty or placeholder for AI-generated nodes

What’s wrong in implementation terms:

AI output includes or implies descriptive content

That content is:

either dropped during normalization, or

mapped to the wrong field, or

not consumed by the node renderer

This is a content plumbing issue, not an AI reasoning issue

Scope of fix:

Ensure AI-generated nodes always set:

data.label (short title)

data.description (expanded detail)

Ensure the renderer consumes data.description

Add a dev warning if an AI-generated node has no description

Do not change user-authored nodes or AI prompts

Explicit non-goals (to avoid regressions)

This task does not include:

AI system prompt changes

Experiment/Explore mode changes

Home Prompt / Chat routing changes

Export bundle changes

Confidence gating or intent logic changes

Those areas are already implemented and should remain untouched.

Summary (one sentence)

The fixes are limited to (1) isolating preview vs committed graph topology and (2) correctly plumbing AI-generated node content into header/body fields — nothing else.
