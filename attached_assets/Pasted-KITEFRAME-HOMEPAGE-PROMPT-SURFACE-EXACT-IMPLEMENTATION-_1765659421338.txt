KITEFRAME — HOMEPAGE PROMPT SURFACE (EXACT IMPLEMENTATION INSTRUCTIONS)

This is NOT a form.
This is a SINGLE prompt surface with layered content.

Treat this like a ChatGPT / Notion AI hero prompt, not a page with multiple sections.


SECTION 1 — REQUIRED VISUAL HIERARCHY (NON-NEGOTIABLE)

All of the following MUST live INSIDE ONE unified prompt container:

1. Header text (black)
2. Subheader text (grey)
3. Prompt input area
4. Upload shortcuts (Figma / Image / Document)
5. Send button (black circular arrow)

Nothing below should be rendered outside the prompt container.


SECTION 2 — PROMPT CONTAINER (SINGLE WRAPPER)

Create ONE container that visually looks like a large input card.

Example constraints (do not deviate conceptually):
- Rounded corners
- White background
- Subtle border or shadow
- Padding on all sides
- Visually reads as “one thing”

This container owns ALL children below.

Do NOT:
- Put header text above the container
- Put upload buttons outside the container
- Put the send button elsewhere on the page


SECTION 3 — HEADER + SUBHEADER (INSIDE PROMPT)

Inside the prompt container, at the TOP:

HEADER:
Text:
"What would you like to build?"

Style:
- Color: Black
- Font size: Large (hero-level)
- Font weight: Semibold / Bold
- Margin-bottom: small

SUBHEADER:
Text:
"Describe your workflow, upload a photo, import from Figma, or start brainstorming with KiteAI"

Style:
- Color: Neutral grey
- Font size: Smaller than header
- Normal weight
- Directly under header

IMPORTANT:
These are NOT labels.
They are part of the prompt surface itself.


SECTION 4 — PROMPT INPUT (PRIMARY INTERACTION)

Below the header/subheader:

- Render a large, borderless textarea or contenteditable
- Placeholder text only (light grey)
- No visible input border
- Input visually blends into the card

Placeholder example:
"Describe what you want to build..."

Rules:
- This input expands vertically
- No boxed input styling
- No label above it
- It must feel like typing into a canvas, not a form field


SECTION 5 — UPLOAD SHORTCUTS (BOTTOM-LEFT, INSIDE PROMPT)

Inside the SAME prompt container, anchored to the BOTTOM-LEFT:

Render THREE compact shortcut cards or pills:

- Figma
- Image
- Document

Each includes:
- Icon
- Label
- Subtext (small)

Placement rules:
- These are NOT centered
- They sit visually in the lower-left corner of the prompt container
- They do not push content upward
- They feel secondary to typing

These must be visually inside the prompt card boundary.


SECTION 6 — SEND BUTTON (BOTTOM-RIGHT, INSIDE PROMPT)

Inside the SAME prompt container, anchored to the BOTTOM-RIGHT:

Render:
- A circular black button
- White right-arrow icon
- Clearly clickable

Rules:
- Button floats within the prompt container
- Not inline with upload buttons
- Visually mirrors ChatGPT send affordance
- Disabled state when input is empty


SECTION 7 — LAYOUT RULES (VERY IMPORTANT)

- Header, input, uploads, and send button are ALL children of the same container
- Use relative positioning on the container
- Use absolute positioning ONLY for:
  - Upload shortcuts (bottom-left)
  - Send button (bottom-right)

Do NOT:
- Split these into multiple components with independent backgrounds
- Stack them as separate sections
- Let the uploads or button escape the container bounds


SECTION 8 — COMMON MISTAKES TO AVOID (PLEASE READ)

❌ Header rendered above the prompt card  
❌ Upload buttons outside the prompt area  
❌ Prompt input boxed separately  
❌ Send button floating on the page edge  
❌ Treating this like a form with labels  

This is a SINGLE COMPOSED SURFACE.


SECTION 9 — ACCEPTANCE CRITERIA

This task is complete ONLY if:

✓ Header and subheader are inside the prompt container
✓ Header is black, subheader is grey
✓ Upload shortcuts are bottom-left INSIDE the prompt
✓ Send button is bottom-right INSIDE the prompt
✓ The entire thing reads as ONE interaction surface
✓ No duplicated backgrounds or cards
✓ No layout drift on resize


SECTION 10 — WHY THIS MATTERS (DO NOT IGNORE)

This prompt surface is the foundation for:
- Chat-style expansion
- Clarification flows
- Vision-based followups
- Pre-project confirmation

If this is implemented incorrectly, ALL downstream UX breaks.


END OF INSTRUCTIONS
