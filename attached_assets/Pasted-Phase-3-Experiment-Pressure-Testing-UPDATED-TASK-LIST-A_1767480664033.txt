Phase 3 — Experiment (Pressure Testing)
UPDATED TASK LIST (Authoritative, Replit-Ready)

This version supersedes the earlier Phase 3 draft.

Phase 3 Goal (Unchanged)

Introduce pressure-testing via Experiments that allow users to explore what-ifs and enhancements without committing changes, using:

Insight-scoped entry points

Deterministic, cached previews

Two-column layout

Explicit Accept / Cancel semantics

Experiments are parallel to Propose Solution, not sequential.

Locked Interaction Decisions (NEW — DO NOT DEVIATE)

These are now authoritative:

Entry point

“Try this as an experiment” appears on each InsightCard

It is a peer action to “Propose Solution”

Relationship to Propose Solution

Experiments do not require a proposal to exist

Experiments may be triggered:

Directly from any Insight with relatedNodeIds

After a proposal is accepted

No sequential dependency

Container behavior

Experiment container uses the same container slot as ProposalPreviewContainer

Proposal and Experiment containers are mutually exclusive

Opening Experiment automatically closes any Proposal container

Card interaction

Clicking an experiment card:

Selects it

Updates preview immediately

Inline expansion for concise details is optional

Preview is always the primary artifact

Explicitly Out of Scope (Still Applies)

Prompt quality improvements

Experiment chaining

Visual node differentiation

Partial acceptance

Persisting experiment history

Task Breakdown
Task 1 — Experiment Entry Point (Insight-Scoped)

Goal: Enable parallel access to experiments.

Add “Try this as an experiment” button to each InsightCard

Button visible when:

Feature flag is enabled

Insight has at least one relatedNodeId

Clicking:

Closes any active Proposal container

Initiates Experiment generation

Opens Experiment container UI

Important:
This button must not depend on Propose Solution state.

Task 2 — Experiment State Model

Create Experiment session state:

interface Experiment {
  id: string;
  insightId: string;
  affectedNodeIds: string[];
  title: string;
  description: string;
  variant: {
    nodes: Node[];
    edges: Edge[];
  };
}

interface ExperimentState {
  experiments: Experiment[]; // exactly 4
  activeExperimentId: string | null;
}


Rules:

Exactly 4 experiments

Generated together

Cached client-side

One active experiment at a time

Task 3 — Experiment Generation (Single Invocation)

Goal: Deterministic pressure-testing options.

One AI call per Experiment session

AI returns exactly 4 experiments

Each experiment includes:

Title

Short description

Nodes / edges only (no full workflow)

Capture snapshotNodes / snapshotEdges once

Cache all experiments in ExperimentState

No regeneration on click or re-render

Task 4 — Experiment Container UI (Two-Column)

Goal: Match Proposal UX for consistency.

Left Column (≈35–40%)

Header: Experiments

Vertical list of 4 experiment cards

Card contents:

Title

One-line description

Card behavior:

Click = select

Optional inline expand (concise only)

Sets activeExperimentId

Right Column (≈60–65%)

Read-only preview canvas

Shows preview for active experiment

Empty state if none selected

Task 5 — Experiment Preview Composition

Goal: Show hypothetical change only.

For active experiment:

previewNodes = [
  ...originNodes,
  ...experiment.variant.nodes
];

previewEdges = [
  ...originEdges,
  ...experiment.variant.edges
];


Rules:

Origin nodes = nodes from affectedNodeIds

Only one experiment visible at a time

Full workflow is never rendered

Task 6 — Accept Experiment (Commit)

Goal: Promote experiment to real workflow.

Replace any “Run Experiment” CTA with Accept

Accept enabled only when an experiment is selected

On Accept:

Clone variant nodes/edges

Strip speculative metadata

Attach metadata:

meta: {
  createdFromInsightId: insightId,
  createdFromExperimentId: experiment.id
}


Commit via single withUndo(...)

Clear Experiment state

Close Experiment container

Task 7 — Cancel Experiment

Goal: Safe discard.

Cancel clears Experiment state

No undo entry

No canvas mutation

Return to normal canvas view

Must mirror Proposal Cancel exactly.

Task 8 — Determinism & Guardrails

Confirm:

Experiments generated once per session

Card clicks never regenerate

Preview uses cached data only

No AI calls after generation

Task 9 — Undo / Redo Validation

Accept creates exactly one undo entry

Undo removes experiment changes

Redo restores them

Cancel creates zero undo entries
