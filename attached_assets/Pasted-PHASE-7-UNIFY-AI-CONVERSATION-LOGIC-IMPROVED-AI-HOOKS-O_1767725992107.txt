PHASE 7 – UNIFY AI CONVERSATION LOGIC (IMPROVED AI HOOKS)

Objective:
Unify HomeScreen chat and in-project KiteAI chat so they share the same underlying AI reasoning logic, using useKiteAIConversation as the canonical conversation engine.

This is an infrastructure unification task, NOT a behavior expansion.

--------------------------------------------------
A. CANONICAL CONVERSATION ENGINE
--------------------------------------------------

Instruction:
Treat useKiteAIConversation as the single source of truth for all AI chat reasoning.

Responsibilities owned by useKiteAIConversation:
- Conversation state machine
- Actionability scoring
- PM depth guards
- Heuristic signal extraction
- Vision signal handling
- Clarification turn tracking
- Fast-path detection

Do NOT:
- Duplicate logic into HomeScreen or KiteAITab
- Re-implement heuristics locally
- Fork the hook per surface

--------------------------------------------------
B. INTEGRATION TARGETS
--------------------------------------------------

Integrate useKiteAIConversation into the following surfaces:

1. HomeScreen (Prompt Chat)
2. KiteAITab (In-Project Chat)

Both surfaces must:
- Use the same hook
- Pass surface context explicitly (home vs project)
- Pass workflow/project context when available

--------------------------------------------------
C. FEATURE FLAGGING (CRITICAL)
--------------------------------------------------

All behavioral enforcement must be gated.

Introduce feature flags:
- ENABLE_UNIFIED_CONVERSATION_ENGINE
- ENABLE_PM_DEPTH_GUARDS_CHAT
- ENABLE_CLARIFICATION_LOOPS_CHAT

V1 DEFAULTS:
- ENABLE_UNIFIED_CONVERSATION_ENGINE = ON
- ENABLE_PM_DEPTH_GUARDS_CHAT = OFF (warn-only)
- ENABLE_CLARIFICATION_LOOPS_CHAT = OFF

--------------------------------------------------
D. V1 BEHAVIOR CONSTRAINTS (NON-NEGOTIABLE)
--------------------------------------------------

During Phase 7 / V1:

- PM depth guards must NOT block user actions
- Clarification loops must NOT auto-trigger
- Fast-paths must NOT skip user-visible steps
- No new rejection or refusal behaviors allowed

Heuristics may:
- Score
- Annotate
- Log
- Surface warnings

Heuristics must NOT:
- Prevent generation
- Prevent proposals
- Prevent experiments
- Change UX flow

Constraints:
