This is well-written. A few things worth tightening before you hand it to Replit:
The session token/flag approach needs more specificity
The task says “pass a session token or flag so the credit middleware treats it as a continuation” but leaves the implementation open. Replit will make a choice here and it may not be the right one. Be explicit: the session ID should be generated client-side on first generation, stored in component state, and passed as a request header or body field on subsequent messages. The middleware checks for its presence — if the session ID exists and matches an active session in a server-side store (or a short-lived signed token), skip deduction. Don’t rely on client-side state alone to gate credits — that’s bypassable.
Add to Task 2: “Session ID should be generated on the client, validated server-side. Do not gate credit deduction purely on a client-passed flag.”
The 50-node cap number needs a source
The task uses 50 nodes as the cap but doesn’t reference where that constant lives. If it’s already defined somewhere (a config constant, a plan limit, anything), Replit should import it rather than hardcode 50 in a new place. If it’s not defined yet, this task should also create that constant so there’s one source of truth.
Add to Task 3: “Use the existing node cap constant if one exists, or define MAX_CANVAS_NODES = 50 in a shared constants file rather than hardcoding in handleSend.”
“Estimated new nodes” is ambiguous
The conservative estimate of 10 nodes is reasonable but the task should specify the fallback behavior more precisely. What happens if the AI would generate exactly 5 nodes and the canvas has 47? The check would incorrectly block it. Consider: run the check against the actual current count, not a pre-generation estimate. If you can’t know the output size, either use the conservative number and document that it may occasionally block valid requests, or check post-generation before applying (which costs a credit but doesn’t corrupt the canvas).
The cleaner approach for now: check currentNodes.length >= 40 as a soft warning and >= 50 as a hard block. Flag this tradeoff explicitly so Replit doesn’t silently pick one.
One missing done condition
Your “done looks like” section doesn’t cover the cap check behavior when the session guard and cap check interact. Specifically: if a user is mid-session (session active, no credit deduction on this turn) and the canvas hits cap — does the session end? It should. Add: “If a canvas cap error occurs during an active session, the session is cleared and the user must start a new optimization request.”
Otherwise the task is tight. The out-of-scope list is doing real work here — explicitly excluding multi-workflow chip UI and subscription gating will prevent scope creep on what’s already a meaty P0.​​​​​​​​​​​​​​​​
