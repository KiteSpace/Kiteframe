PHASE: V1 STABILIZATION – MERGE-SAFE WORKFLOW MUTATION FIX

GOAL
Fix a critical defect where follow-up chat actions:
- fail to merge into existing workflows
- inject orphan nodes
- bypass decision repair
- create invalid graph states before Test Flight

This fix must guarantee that ALL chat-driven workflow edits:
- are merge-safe
- are structurally valid
- cannot leave the canvas in a broken intermediate state

THIS IS A CORRECTNESS FIX, NOT A UX CHANGE.

--------------------------------------------------
LOCKED PRINCIPLES (DO NOT VIOLATE)
--------------------------------------------------

1. NO ORPHAN NODES
   - A node may never be added unless it has at least one valid incoming edge
   - Nodes without incoming edges must abort the mutation

2. MERGE-FIRST ENFORCEMENT
   - Follow-up chat edits MUST modify the active workflow
   - Parallel workflows may NOT be created unless explicitly requested

3. DECISION COMPLETENESS IS NON-NEGOTIABLE
   - Every decision node MUST have ≥2 outgoing edges
   - Every outgoing edge MUST have a semantic label

4. REPAIR BEFORE SUGGEST
   - If a defect is auto-repairable, do NOT surface Propose / Experiment

--------------------------------------------------
IMPLEMENTATION TASKS (STRICT ORDER)
--------------------------------------------------

TASK 1 — ADD MERGE-SAFE MUTATION CONTRACT
Location:
  client/src/workflow/mutation/applyChatWorkflowMutation.ts

Add a new mutation contract wrapper:

interface WorkflowMutationResult {
  success: boolean;
  reason?: string;
  mutatedNodes: Node[];
  mutatedEdges: Edge[];
}

Rules enforced BEFORE mutation is applied:
- All new nodes must reference an existing node ID as attachment
- All new edges must reference valid source + target IDs
- No node may be created without an incoming edge

If ANY rule fails:
- Abort mutation
- Log error
- Return success=false
- DO NOT TOUCH CANVAS STATE

--------------------------------------------------

TASK 2 — REQUIRE EXPLICIT ATTACHMENT TARGET
Location:
  client/src/ai/workflowMutation/resolveAttachmentTarget.ts

Implement:
- resolveAttachmentTarget(existingGraph, mutationIntent)

Rules:
- Follow-up mutations MUST resolve to an existing node ID
- Labels (e.g. "Verification Failed") are INVALID references
- If no valid attachment target is found → abort mutation

Return:
  { targetNodeId: string } | null

Null MUST abort the mutation.

--------------------------------------------------

TASK 3 — BLOCK ORPHAN NODE INSERTION
Location:
  applyChatWorkflowMutation.ts

Before committing nodes:
- Validate each new node has ≥1 incoming edge
- If not, reject mutation with reason: "Orphan node prevented"

This must run EVEN IF AI output is otherwise valid JSON.

--------------------------------------------------

TASK 4 — FORCE DECISION REPAIR PRE-FLIGHT
Location:
  client/src/workflow/lifecycle/runWorkflowRepairs.ts

Move Decision Repair execution to:
- AFTER chat mutation
- BEFORE Test Flight
- BEFORE Propose / Experiment logic

Decision Repair must:
- Add missing Yes/No (or semantic equivalent) labels
- Add missing opposite branches
- Route to existing nodes where possible
- Create ONE fallback node only if no valid target exists

--------------------------------------------------

TASK 5 — SUPPRESS PROPOSE / EXPERIMENT FOR REPAIRABLE ISSUES
Location:
  client/src/diagnostics/DiagnosticsEngine.ts

If issue type is:
- Incomplete decision
- Unlabeled decision edge
- Dangling decision path

AND Decision Repair fixed it:
- Do NOT show Propose
- Do NOT show Experiment
- Mark as "Auto-repaired" in diagnostics

--------------------------------------------------

TASK 6 — ENFORCE MERGE MODE FOR FOLLOW-UP CHAT
Location:
  client/src/ai/intent/detectMergeBranchIntent.ts

If intent === "merge":
- Disallow creation of new workflows
- Disallow workflow duplication
- Require mutation to reuse existing IDs
- Abort if mutation attempts to create parallel root nodes

--------------------------------------------------

TASK 7 — AUDIT & VISIBILITY
Location:
  client/src/ai/explainability/decisionCapture.ts

Extend DecisionSnapshot with:
  mutationSafety: {
    mergeEnforced: boolean;
    orphanPreventionTriggered: boolean;
    decisionRepairApplied: boolean;
    mutationAborted?: string;
  }

Expose in WhyInspector under:
  "Automatic Safety Corrections"
