Phase 1 — Propose Solution (Preview-Only)
Goal (Do Not Deviate)

Render a deterministic, read-only Proposed Solution preview in a two-column horizontal layout, accessible from Insights → Propose Solution, with Cancel only.

No workflow commits

No undo/redo writes

No mutation of existing canvas state

This phase exists solely to validate rendering, layout, and trust mechanics.

Locked Constraints (Authoritative)

These are non-negotiable:

Proposal state is client-only

Only one active proposal at a time

Proposal does not persist across refresh

Preview uses a separate KiteFrameCanvas instance

Preview canvas uses readOnly={true}

Preview uses cloned nodes/edges only

No withUndo() or saveToHistory() calls in this phase

No visual changes to nodes or edges

Distinction lives entirely in container chrome

Feature is gated to Insights → Propose Solution only

Explicitly Out of Scope (DO NOT IMPLEMENT)

Accept / Commit behavior

Alternative Approach

Experiment flow

Editing previewed workflows

Versioning

Persistence

History entries

AI regeneration on re-render

Task Breakdown
Task 1 — Feature Flag

Goal: Ensure safe rollout.

Add a feature flag (env or config based) for PROPOSE_SOLUTION_PREVIEW

Gate all UI entry points behind this flag

Default: off

Task 2 — Insights Entry Point

Goal: Create the user entry into the flow.

In the Insights tab, add a button labeled:

Propose Solution

Button only renders when:

Feature flag is enabled

No active proposal is present

Click behavior:

Triggers proposal generation (see Task 3)

Opens the Proposal container UI

Task 3 — Proposal Generation (Single Variant Only)

Goal: Generate a deterministic proposed workflow.

On button click:

Call AI generation once

Request one Proposed workflow only

Response must include:

Nodes

Edges

Positions

Store result in local component state:

proposedWorkflow: {
  nodes: Node[];
  edges: Edge[];
}


Do not write to canvas state

Do not store on server

Important:

Clone data immediately after generation

Generate unique node and edge IDs if needed

Validate edge → node references before render

Task 4 — Proposal Container UI (Two-Column Layout)

Goal: Render proposal in a horizontal, inspectable layout.

Use existing layout primitives (ResizablePanelGroup).

Left Column (≈35–40%)

Contents:

Header: Proposed Solution

Subtext:

Here’s what I recommend based on what you have so far.

Approach title (static for Phase 1)

Short descriptive paragraph (AI-generated or placeholder)

This column is textual and decision-oriented.

Right Column (≈60–65%)

Contents:

Header: Proposed workflow

Read-only preview canvas

Implementation:

Render separate KiteFrameCanvas instance

Pass:

readOnly={true}
nodes={clonedProposedNodes}
edges={clonedProposedEdges}


Enable pan & zoom

Disable all editing affordances

Task 5 — Preview Canvas Behavior

Goal: Make preview feel real but non-committal.

Pan & zoom: enabled

Node selection: optional (hover OK)

Editing: disabled

No context menus

No keyboard shortcuts

No drag handles

Below the canvas, render helper text:

You can edit this workflow after accepting it.

(Exact copy required.)

Task 6 — Cancel Behavior

Goal: Safe exit with zero side effects.

Render Cancel button in container footer

On Cancel:

Clear proposal state

Unmount proposal container

Return user to normal canvas view

Rules:

No confirmation dialog

No undo history entry

No canvas mutations

Task 7 — Guardrails & Cleanup

Goal: Prevent accidental regressions.

Ensure proposal preview:

Never calls setNodes / setEdges

Never calls withUndo

Ensure proposal state:

Is cleared on unmount

Cannot exist alongside another proposal

Ensure UI:

Does not overlap or mutate the main canvas

Is visually distinct only via container chrome

Validation Checklist (Must Pass Before Merge)

 Preview renders without mutating main canvas

 Pan & zoom work in preview

 Editing is impossible in preview

 Cancel leaves no residue

 Reload clears proposal

 Feature flag disables entire flow cleanly

 No undo history entries created
