
KITEFRAME – RIGHT PANEL REFACTOR (KITEAI + NOTION-STYLE PROJECT TAB + SIMPLIFIED LAYERS)
Target: Replit implementation guide (NO HALLUCINATIONS)

IMPORTANT EXECUTION NOTES
- Only modify the files explicitly listed in this document.
- Do NOT create new concepts, features, or behaviors that are not described here.
- When something is unclear or a dependency is missing, STOP and surface the question to the user instead of guessing.
- Preserve all existing behavior except where this doc explicitly overrides or consolidates it.

HIGH-LEVEL GOALS
1) Refactor the existing right-side ProjectPanel into:
   - Tab 1: KiteAI (chat-based assistant for the current project/workflows)
   - Tab 2: Project (a single, Notion-style continuous document for project + workflows + PRDs + notes + sources)
   - Tab 3: Layers (simplified layer/workflow overview)
2) Make the Project tab behave as ONE scrollable, Notion-like document (Option A).
3) Within the Project tab, show workflow-level details inline when the user selects a workflow (Option C).
4) Do NOT break the existing PRD engine, notes system, or sources system. Instead, integrate them into the new Project tab.
5) Keep the visual style aligned with current Kiteframe UI but simplify toward a more “DOM-like” / Notion-like layout (less boxy cards, more vertical sections + subtle dividers).

2.2 Update KiteAIChat to support “panel” mode
File: client/src/components/KiteAIChat.tsx

Currently, KiteAIChat manages:
- Floating positioning (absolute, draggable, resizable)
- Internal messages state
- Input, send, AI calls

We need to make it aware of a new prop:

type KiteAIChatProps = {
  mode?: 'floating' | 'panel';
  projectId?: string;
  projectName?: string;
  nodes: Node[];
  edges: Edge[];
  canvasObjects: CanvasObject[];
  // existing props like onApplyWorkflow, etc., should remain
};

Implementation details:

(1) Default mode to 'floating' for backward compatibility:
  const effectiveMode = props.mode ?? 'floating';

(2) Conditional layout:
- If mode === 'floating':
  - Keep existing behavior: absolute positioning, drag, resize, close button, etc.
- If mode === 'panel':
  - DO NOT:
    - Render draggable/resize handles
    - Attach window mousemove/mouseup listeners
    - Use absolute/fixed positioning
  - INSTEAD:
    - Render as a normal flex column that fills parent height:
      <div className="flex flex-col h-full border-l border-border bg-background">
        {/* header with title + small description */}
        {/* messages list */}
        {/* input bar */}
      </div>

- You can keep the same message list + input components; only container styling & positioning logic changes.

(3) Gate drag/resize logic:
- Wrap all drag/resize logic in:
  if (effectiveMode === 'floating') {
    // existing window event listeners and drag state
  }

- If mode === 'panel', skip registering those listeners and hide any drag UI.

(4) Optional: message persistence per project (simple version)
- For now, you can keep messages in local component state (no storage).
- If you want to give better UX, you may:
  - Initialize messages from localStorage key: kiteframe-kiteai-chat-${projectId}
  - Save every time messages change.
- This is optional; do NOT overcomplicate unless everything else is stable.

3.3 Workflows section (list + selection, inline detail)
We want:

- A “Workflows” section listing all workflows + standalone nodes.
- Clicking a workflow row selects it and reveals the “Selected Workflow Detail” section further down in the same Project tab.

Implementation:

(1) Get workflows and standalone nodes:
- Use existing FlowDetection / groupWorkflows utilities:
  - import { detectFlows } from '@/lib/kiteframe/utils/FlowDetection';
- Run detectFlows(nodes, edges) to get connected components.
- For each component:
  - Count edges and nodes:
    - If edgesCount >= 2 AND nodesCount >= 2 → treat as a workflow group.
    - Else → treat its nodes as "standalone nodes".
- Build a data structure:

  type WorkflowSummary = {
    id: string;             // stable identifier, e.g., group root node id or computed hash
    name: string;           // from workflowNameStore or fallback like "Workflow 1"
    nodeIds: string[];
    edgeIds: string[];
    nodeCount: number;
    edgeCount: number;
    status?: 'todo' | 'in-progress' | 'done'; // existing badge system, if present
  };

  type StandaloneNodeSummary = {
    nodeId: string;
    label: string;
    status?: 'todo' | 'in-progress' | 'done';
  };

- Prefer using the existing workflowNameStore (if available) to supply names.

(2) Render Workflows section:

- In ProjectDocTab, include a section:

  <section>
    <header className="flex items-center justify-between mb-2">
      <h2 className="text-sm font-semibold text-muted-foreground uppercase tracking-wide">
        Workflows
      </h2>
      {/* Optional: small search input */}
    </header>

    {/* List of workflow rows */}
    <div className="space-y-1">
      {workflowSummaries.map((wf) => (
        <button
          key={wf.id}
          className={cn(
            "w-full text-left px-2 py-1 rounded hover:bg-accent/60 text-sm flex items-center justify-between",
            wf.id === selectedWorkflowId && "bg-accent"
          )}
          onClick={() => setSelectedWorkflowId(wf.id)}
        >
          <div className="flex items-center gap-2">
            {/* tiny status pill if available */}
            {/* name and counts */}
            <span className="font-medium">{wf.name}</span>
            <span className="text-xs text-muted-foreground">
              {wf.nodeCount} nodes · {wf.edgeCount} edges
            </span>
          </div>
        </button>
      ))}
    </div>

    {/* Standalone nodes (optional separate sub-section) */}
    {standaloneNodes.length > 0 && (
      <div className="mt-3">
        <div className="text-xs uppercase text-muted-foreground mb-1">
          Standalone nodes
        </div>
        <div className="space-y-1">
          {standaloneNodes.map((sn) => (
            <div key={sn.nodeId} className="px-2 py-1 text-sm text-muted-foreground">
              {sn.label}
            </div>
          ))}
        </div>
      </div>
    )}
  </section>

(3) Selected Workflow detail (inline, Option C)
- After the Workflows section, render a “Selected Workflow” section if selectedWorkflowId is set:

  const selectedWorkflow = workflowSummaries.find(w => w.id === selectedWorkflowId);
