KITEFRAME — ARCHITECTURAL HARDENING: COMPONENT NAMING + ROUTING FIX (OPTION A)

PURPOSE
We are preventing repeated regressions caused by conflating:
- chat vs project
- workflow vs project
- exploration vs committed state

This task explicitly encodes architectural invariants into:
1) component naming
2) routing boundaries

These changes are REQUIRED before proceeding with further feature work.

---------------------------------------------------------------------

PART 1 — COMPONENT NAMING (ARCHITECTURAL HARDENING)

GOAL
Make it impossible (or obviously wrong) to:
- route Home Prompt into project context
- create a project implicitly
- treat chat as always project-bound

Names must encode whether a project is required.

---------------------------------------------------------------------

1. SPLIT CHAT INTO BRAIN + SHELLS (DO NOT FORK LOGIC)

A) RENAME / EXTRACT SHARED CHAT LOGIC

Create or rename the shared, project-agnostic chat logic to:

  KiteAIChatBrain

Responsibilities:
- message handling
- intent classification
- workflow generation
- quick actions
- currentWorkflowDraft
- Create Workflow intent (but NOT routing or project creation)

KiteAIChatBrain MUST:
- NOT know about routes
- NOT know about panels
- NOT create projects
- NOT assume a projectId exists

This is the single “chat brain” used everywhere.

---------------------------------------------------------------------

B) EXPLICIT CHAT SHELLS (ENCODE PROJECT OWNERSHIP)

Create or rename the following shells:

1) FullScreenChatShell

Used at:
  /app/chat

Guarantees:
- NO projectId
- NO canvas
- NO project panel
- FULL-SCREEN chat only
- Uses KiteAIChatBrain internally

This shell represents:
  “Exploration / generation before a project exists”

Optional guard (recommended):
  If a projectId is ever passed here, throw an error.

---------------------------------------------------------------------

2) ProjectChatShell

Used at:
  /app/project/:id

Guarantees:
- projectId REQUIRED
- canvas mounted
- project panel visible
- Uses KiteAIChatBrain internally

This shell represents:
  “Committed work inside a project”

Optional guard (recommended):
  If projectId is missing, throw an error.

---------------------------------------------------------------------

C) WORKFLOW EDITOR NAMING

Rename (component name, not necessarily path):

  workflow-editor  →  ProjectWorkflowEditor

This makes it explicit:
- A project MUST exist
- This is not a valid Home Prompt target

---------------------------------------------------------------------

PART 2 — ROUTING FIX (OPTION A, REQUIRED)

GOAL
Support chat without a project under the authenticated /app root.

Project creation must ONLY occur when the user clicks “Create Workflow”.

---------------------------------------------------------------------

2. ROUTING MODEL (FINAL)

Routes under /app:

/app/chat
  - Renders FullScreenChatShell
  - NO project context
  - Used ONLY for Home Prompt + exploration

/app/project/:id
  - Renders ProjectWorkflowEditor
  - Includes ProjectChatShell
  - Requires projectId

---------------------------------------------------------------------

3. HOME PROMPT ROUTING (CRITICAL)

Modify Home Prompt submit handler to:

  navigate('/app/chat?prompt=...')

Home Prompt MUST NOT:
- navigate to /app/project/:id
- create a project
- create a workflow tab
- mount ProjectWorkflowEditor

Home Prompt is a PURE ENTRY POINT INTO CHAT.

---------------------------------------------------------------------

4. FULLSCREEN CHAT BEHAVIOR

FullScreenChatShell must:
- Read prompt from query (?prompt=...)
- Inject it into KiteAIChatBrain
- Continue conversation inline
- Maintain currentWorkflowDraft
- Render WorkflowDraftActions

NO project is created here.

---------------------------------------------------------------------

5. CREATE WORKFLOW HANDLER (ONLY PLACE PROJECT IS CREATED)

“Create Workflow” button (inside FullScreenChatShell):

On click:
- Create new project
- Create workflow tab
- Navigate to /app/project/:id
- Mount ProjectWorkflowEditor
- Load the generated workflow

This is the ONLY place project creation is allowed.

---------------------------------------------------------------------

PART 3 — ACCEPTANCE CRITERIA (PASS / FAIL)

PASS if:
- Home Prompt → /app/chat
- Full-screen chat appears
- No projectId exists
- No canvas or project panel visible
- Chat continues inline

PASS if:
- Clicking “Create Workflow”:
  - Creates project
  - Navigates to /app/project/:id
  - Shows canvas + project panel

FAIL if:
- Any project is created on Home Prompt submission
- workflow-editor loads before Create Workflow
- Chat appears inside project panel immediately

---------------------------------------------------------------------

NON-NEGOTIABLE INVARIANT (FINAL)

- /app = authenticated shell
- /app/chat = chat WITHOUT project
- /app/project/:id = chat WITH project
- Project creation ONLY via “Create Workflow”

Do NOT collapse these again.
Do NOT auto-create projects.
Do NOT infer project existence from chat.
