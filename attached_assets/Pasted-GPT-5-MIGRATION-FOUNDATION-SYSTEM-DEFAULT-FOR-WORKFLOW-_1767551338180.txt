GPT-5 MIGRATION FOUNDATION
SYSTEM DEFAULT FOR WORKFLOW REASONING
AUTHORITATIVE TASK FILE

⸻

OBJECTIVE

Make GPT-5 the default and enforced model for all workflow generation and reasoning tasks, while preserving a user-selectable “Choose model” option for general chat only.

This migration MUST preserve:
	•	Determinism (Phases 2–4)
	•	Auditability (Phase 5)
	•	Safety guarantees (Accept / Cancel / Undo)
	•	Vision handling (image import)

This is an architectural change, not a model swap.

⸻

NON-NEGOTIABLE RULES
	1.	Workflow reasoning MUST NOT depend on user model selection.
	2.	A workflow session MUST be locked to one model.
	3.	Model identity MUST be recorded in audit metadata.
	4.	No feature may hardcode a model after this migration.
	5.	Vision ingestion MUST remain separate from reasoning.

⸻

TASK A — INTRODUCE TASK-TYPE ROUTING (REQUIRED)

Create a central AI routing abstraction.

Add a new enum:

taskType:
	•	workflow_reasoning
	•	workflow_experiments
	•	prd_generation
	•	vision_ingestion
	•	general_chat

Create a single entry point, e.g.:

aiRouter.chat({
taskType,
messages,
sessionId?,
metadata?
})

ALL existing aiClient.chat() calls MUST be routed through this abstraction.

No feature file may directly specify a model after this change.

⸻

TASK B — DEFINE SYSTEM DEFAULT MODEL POLICY

Implement routing rules:
	•	workflow_reasoning → GPT-5 (system enforced)
	•	workflow_experiments → GPT-5 (system enforced)
	•	prd_generation → GPT-5 (system enforced)
	•	vision_ingestion → GPT-4o (until GPT-5 vision parity confirmed)
	•	general_chat → user-selected model (current behavior)

User Settings:
	•	“Choose model” applies ONLY to general_chat
	•	Workflow reasoning ignores user model choice

UI copy (internal or visible):
“Workflow reasoning uses the system-recommended model for reliability.”

⸻

TASK C — REMOVE ALL HARDCODED MODELS (BLOCKING)

Refactor the following to remove hardcoded model strings:
	•	prdEngine.ts
	•	semanticWorkflowGenerator.ts
	•	any feature file specifying model: ‘gpt-4o’

These must call aiRouter.chat({ taskType: … }) instead.

This task is REQUIRED before GPT-5 is enabled.

⸻

TASK D — SESSION-LEVEL MODEL LOCK (CRITICAL)

Implement model locking for determinism-critical flows:
	•	Propose Solution session
	•	Experiment session
	•	(Optional) PRD generation session

When a session starts:
	•	Record sessionModelLock = { provider, model }

All AI calls within that session MUST use the locked model.

If user changes model settings mid-session:
	•	Do NOT apply change to current session
	•	Apply only to future general_chat or future sessions

No silent behavior changes are allowed.

⸻

TASK E — RECORD MODEL IDENTITY IN PHASE 5 METADATA

Extend DecisionSnapshot to include:
	•	providerUsed
	•	modelUsed
	•	routerTaskType
	•	usedFallback (boolean)
	•	fallbackModelUsed (optional)

Ensure:
	•	Metadata survives undo / redo
	•	Metadata is included in audit exports
	•	Metadata is immutable once written

This is REQUIRED for Phase 5 compliance.

⸻

TASK F — HARDEN STRUCTURED OUTPUT PARSING

Replace brittle regex-based JSON extraction with:
	•	A strict JSON envelope requirement OR
	•	A tolerant parser that supports:
	•	raw JSON
	•	fenced code blocks
	•	whitespace noise

Add schema validation (Zod or equivalent) at the boundary.

If parsing fails:
	1.	Regenerate once using the SAME model
	2.	If still invalid, surface controlled error state
	3.	Do NOT switch models silently

⸻

TASK G — FALLBACK STRATEGY (CONTROLLED)

Implement explicit fallback rules:
	•	If GPT-5 fails for workflow_reasoning:
	•	Retry once with GPT-5
	•	Then fall back to GPT-4o
	•	Mark metadata:
usedFallback = true
fallbackModelUsed = ‘gpt-4o’
	•	Increase uncertaintyLevel

Vision fallback logic remains unchanged.

⸻

TASK H — FEATURE FLAG GPT-5 ROLLOUT

Add feature flag:

ENABLE_GPT5_WORKFLOW_REASONING

Behavior:
	•	OFF → current routing behavior
	•	ON → GPT-5 enforced for workflow_reasoning + experiments + PRD

This flag must gate routing, not UI.

⸻

TASK I — SETTINGS UX ADJUSTMENT (REQUIRED)

Update Settings behavior:
	•	“Choose model” affects:
	•	general chat ONLY
	•	Workflow reasoning does not change when user switches models

If needed, add copy:
“Workflow generation uses a system-recommended model for consistency and auditability.”

No advanced override in this phase.

⸻

TASK J — VALIDATION & ACCEPTANCE CHECKLIST

Migration is complete only if:
	•	GPT-5 is default for all workflow reasoning
	•	User cannot downgrade workflow reasoning model
	•	Sessions are model-locked
	•	Model identity is auditable
	•	No hardcoded models remain
	•	Vision ingestion remains functional
	•	General chat model selection still works
	•	Phase 2–5 guarantees remain intact

⸻

FINAL INSTRUCTION

This migration MUST land before:
	•	Any GPT-5 prompt tuning
	•	Any Phase 4 heuristic expansion
	•	Any enterprise rollout

If any task is unclear, ask before implementing. Silent assumptions are not acceptable.
