KITEFRAME — KITEAI INTELLIGENCE PHASE 4
=====================================

GOAL
----
Improve KiteAI usefulness and trust by:
1) Making it aware of workflow maturity (draft vs stable)
2) Asking follow-up questions ONLY when confidence is medium
3) Surfacing AI insights as inline, dismissible “chips” in PRDs and canvas

---------------------------------------
SECTION 1 — WORKFLOW MATURITY AWARENESS
---------------------------------------

DEFINITION
----------
Workflow maturity is a derived state, not user-entered.

States:
- "draft": exploratory, incomplete, or unstable
- "stable": sufficiently defined to reason about behavior/requirements

Maturity is computed, not stored.

---------------------------------------
1.1 Create maturity utility
---------------------------------------

File:
client/src/ai/workflowMaturity.ts

Code:
-----
export type WorkflowMaturity = 'draft' | 'stable';

export function computeWorkflowMaturity(input: {
  nodeCount: number;
  edgeCount: number;
  hasDecisionNodes: boolean;
  hasInputs: boolean;
  hasOutputs: boolean;
}): WorkflowMaturity {
  if (
    input.nodeCount < 4 ||
    input.edgeCount < 3 ||
    !input.hasInputs ||
    !input.hasOutputs
  ) {
    return 'draft';
  }

  return 'stable';
}

---------------------------------------
1.2 Inject maturity into KiteAI context
---------------------------------------

Modify:
client/src/components/KiteAIChat.tsx

Before AI request:
------------------
import { computeWorkflowMaturity } from '@/ai/workflowMaturity';

const maturity = computeWorkflowMaturity({
  nodeCount: currentNodes.length,
  edgeCount: currentEdges.length,
  hasDecisionNodes: currentNodes.some(n => n.type === 'condition'),
  hasInputs: currentNodes.some(n => n.type === 'input'),
  hasOutputs: currentNodes.some(n => n.type === 'output'),
});

Pass maturity into AI context:
------------------------------
const aiContext = {
  workflowMaturity: maturity,
  ...
};

---------------------------------------
1.3 Update system prompts to respect maturity
---------------------------------------

Append to ALL system prompt files:

If workflowMaturity === "draft":
- Focus on clarification, risks, and missing structure
- Do NOT generate acceptance criteria or hard requirements

If workflowMaturity === "stable":
- You MAY generate requirements, acceptance criteria, and edge cases

---------------------------------------
SECTION 2 — FOLLOW-UP QUESTIONS (CONFIDENCE-BASED)
---------------------------------------

RULE
----
KiteAI may ask follow-up questions ONLY when:
0.4 ≤ confidence < 0.7

Never ask follow-ups when:
- confidence < 0.4  → stay silent
- confidence ≥ 0.7 → proceed with analysis

---------------------------------------
2.1 Add follow-up generator
---------------------------------------

File:
client/src/ai/followUpGenerator.ts

Code:
-----
export function generateFollowUps(context: {
  maturity: 'draft' | 'stable';
  role: 'pm' | 'designer' | 'hybrid';
}): string[] {
  if (context.maturity === 'draft') {
    return [
      'What is the primary user goal this workflow is meant to support?',
      'Are there alternative paths or failure cases not shown yet?',
      'Is this intended to be exploratory or production-ready?'
    ];
  }

  return [
    'Are there constraints or edge cases not represented here?',
    'Should this workflow support future variants?'
  ];
}

---------------------------------------
2.2 Gate follow-ups in KiteAIChat
---------------------------------------

Modify:
client/src/components/KiteAIChat.tsx

After confidence calculation:
-----------------------------
if (confidence >= 0.4 && confidence < 0.7) {
  const followUps = generateFollowUps({ maturity, role });

  setMessages(prev => [
    ...prev,
    {
      role: 'assistant',
      content: 'Before going further, I need clarification:',
      followUps
    }
  ]);

  return;
}

---------------------------------------
SECTION 3 — AI INSIGHT CHIPS (INLINE UX)
---------------------------------------

DEFINITION
----------
Insight chips are:
- Short, non-blocking AI observations
- Anchored to a workflow, node, or PRD section
- Dismissible
- Non-conversational (not chat messages)

---------------------------------------
3.1 Insight data model
---------------------------------------

File:
client/src/ai/insights.ts

Code:
-----
export type AIInsight = {
  id: string;
  level: 'info' | 'warning' | 'risk';
  message: string;
  targetType: 'workflow' | 'node' | 'prd-section';
  targetId: string;
  createdAt: number;
};

---------------------------------------
3.2 Insight generation rules
---------------------------------------

Insights are created when:
- maturity === 'draft' AND missing structure is detected
- stable workflow has ambiguous transitions
- PRD section is stale vs workflow hash

Insights MUST:
- Be ≤ 140 characters
- Never suggest implementation details
- Never repeat chat output

---------------------------------------
3.3 Insight store
---------------------------------------

File:
client/src/stores/aiInsightStore.ts

Use:
- projectId scoped
- localStorage-backed

Key:
kiteframe-ai-insights-${projectId}

---------------------------------------
3.4 PRD inline rendering
---------------------------------------

client/src/components/panels/ProjectPanel/SpecsTab.tsx

- Render AIInsight chips above section header
- Chips are small, muted, left-aligned
- Clicking chip scrolls to relevant workflow or node
- “Dismiss” hides chip (local only)

---------------------------------------
3.5 Canvas rendering (nodes)
---------------------------------------

Modify:
Node renderer components

If node has insights:
---------------------

---------------------------------------
SECTION 4 — NON-GOALS (IMPORTANT)
---------------------------------------

DO NOT:
- Auto-edit workflows
- Auto-regenerate PRDs
- Ask questions when confidence is low or high
- Store insights in cloud DB yet
- Let AI control UI state

---------------------------------------
EXPECTED OUTCOME
---------------------------------------

After this phase:
- KiteAI behaves like a senior PM/Designer reviewer
- It knows when a workflow is “too early”
- It asks smart questions ONLY when appropriate
- It provides quiet, contextual guidance instead of chat spam
- Users trust AI signals rather than fighting them
