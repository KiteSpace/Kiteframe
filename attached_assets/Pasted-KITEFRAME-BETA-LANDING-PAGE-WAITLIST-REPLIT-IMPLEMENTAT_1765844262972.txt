KITEFRAME — BETA LANDING PAGE + WAITLIST
REPLIT IMPLEMENTATION INSTRUCTIONS
=================================

GOAL
----
Introduce a non-authenticated landing page that:
1) Clearly communicates Kiteframe is in private beta
2) Allows beta-approved users to authenticate and enter the product
3) Prevents non-beta users from accessing the Home Screen
4) Allows non-beta users to join a waitlist via email
5) Uses the SAME visual language as the Home prompt (no modals)
6) Uses the Kiteframe ambient gradient + a lightweight interactive canvas preview

--------------------------------
SECTION 1 — ROUTING & ACCESS FLOW
--------------------------------

1. Add a new public route:
   Path: /
   Component: LandingPage.tsx

2. Change existing Home behavior:
   - HomeScreen and WorkflowEditor MUST require:
     user.isBeta === true
   - If user is unauthenticated OR authenticated but not beta:
     redirect to /

3. Auth flow rules:
   - OAuth login is allowed for everyone
   - Authorization happens AFTER auth
   - Post-auth redirect logic:
     if (user.isBeta) → /home
     else → /waitlist

--------------------------------
SECTION 2 — USER MODEL CHANGES
--------------------------------

Extend User model (DB or equivalent):

User {
  id
  email
  authProvider
  isBeta: boolean (default false)
  betaGrantedAt?: Date
  waitlistRequestedAt?: Date
}

--------------------------------

Show inline form (NO modal):

  Options:
    - Product Management
    - Design
    - Engineering
    - Founder / Solo Builder

"Join the Waitlist"

On submit:
- Save waitlistRequestedAt
- Persist email
- Show confirmation state inline:
  "You're on the list. We'll be in touch."

SECTION 7 — POST-AUTH BETA GATE
--------------------------------

After OAuth completes:

1. Load user record
2. If user.isBeta === true:
     redirect to /home
3. If user.isBeta === false:
     redirect to /waitlist-authenticated
