KITEFRAME — QUESTIONS FOR REPLIT
HOMEPAGE PROMPT, ATTACHMENTS, PRD GENERATION

PURPOSE
These questions are required to understand the current implementation and architecture so that accurate, low-iteration implementation instructions can be produced for:
- Homepage prompt behavior
- Attachment previews (Figma, image, document)
- Chat transition flow
- Optional auto-generation of first draft PRD after project creation

--------------------------------------------------
SECTION 1 — HOMEPAGE PROMPT & CHAT TRANSITION
--------------------------------------------------

1. Where is the homepage prompt input state owned?
   - HomeScreen?
   - PreProjectChat?
   - A shared hook or global store?
   - When transitioning to full-screen KiteAI chat, does the component remount or persist state?

2. What logic currently determines when the homepage enters “chat mode”?
   - Boolean flag (e.g. isChatActive)?
   - Conversation state machine?
   - Route change or conditional render?
   - Is this logic shared with image/Figma flows or duplicated?

3. Does the homepage prompt use the same useKiteAIConversation hook as KiteAIChat?
   - If yes, are attachments already part of the same conversation state?
   - If no, how is data bridged when transitioning?

--------------------------------------------------
SECTION 2 — ATTACHMENT DATA MODEL
--------------------------------------------------

4. How are homepage attachments currently represented in code?
   - Is there a unified attachment type?
   - Existing fields (type, url, thumbnailUrl, fileName, metadata)?

5. Where are attachments stored during the pre-project prompt phase?
   - Local component state?
   - Global store?
   - Inside the AI conversation message payload?

6. When entering KiteAIChat, are attachments:
   - Passed through directly?
   - Re-fetched?
   - Reconstructed from another source?

--------------------------------------------------
SECTION 3 — ATTACHMENT PREVIEW RENDERING
--------------------------------------------------

7. Does KiteAIChat currently render any attachment previews?
   - If yes, where in the component tree?
   - Are they message-scoped or conversation-scoped?

8. Is there an existing reusable attachment or image preview component?
   - If yes, file path?
   - If no, is adding a new generic AttachmentPreview component acceptable?

9. Is there an existing modal / lightbox component suitable for image expansion?
   - If yes, where?
   - If no, should one be introduced?

--------------------------------------------------
SECTION 4 — PROJECT CREATION CONFIRMATION STEP
--------------------------------------------------

10. Where is the “I have enough context to create your workflow” confirmation UI implemented?
    - File and component name?
    - Is it controlled by AI state (execution-ready) or UI logic?

11. Is the “Start Project” action already gated by a boolean or guard?
    - Variable / function name?
    - Can it be extended to require a checkbox state?

12. Does project creation currently accept options or flags?
    - Example: createProject({ workflow })
    - Or can we add: createProject({ workflow, autoGeneratePRD })

--------------------------------------------------
SECTION 5 — PRD GENERATION PIPELINE
--------------------------------------------------

13. Is PRD generation currently only user-initiated from the Specs tab?
    - Or does any auto-generation path already exist?

14. Is there a single function responsible for PRD generation?
    - generateWorkflowPRD?
    - generateProjectPRD?
    - Or embedded inside UI components?

15. Can PRD generation safely run immediately after workflow creation?
    - Are workflow IDs persisted by then?
    - Are semantic hashes available?
    - Any race conditions to be aware of?

--------------------------------------------------
SECTION 6 — PRD STATE & DRAFT METADATA
--------------------------------------------------

16. Do PRD sections already support metadata such as:
    - generatedAt
    - draft / autoGenerated flags
    - version numbers?

17. How does manual edit protection work today?
    - Will auto-generated PRDs respect manualEditedAt logic?

--------------------------------------------------
SECTION 7 — PERFORMANCE & UX SAFETY
--------------------------------------------------

18. Is PRD generation synchronous or async?
    - Does it show loading state?
    - Can it run in background after navigation?

19. Is there an existing analytics or logging convention?
    - Event naming?
    - Prefixes (e.g. [KiteAI])?

--------------------------------------------------
SECTION 8 — EDGE CASES
--------------------------------------------------

20. If the user cancels during the homepage prompt phase:
    - Should attachments be cleared?
    - Should conversation state reset?

21. Are multiple attachments supported today?
    - If yes, should multiple previews render (stacked)?
    - If no, should MVP limit to one attachment?

--------------------------------------------------
END OF QUESTIONS
--------------------------------------------------

NOTE
These answers are required before writing final Replit execution instructions.
Without them, implementation risks duplicated state, lost attachments,
race conditions, and UI inconsistencies.
