KITEFRAME — PERMANENT FIX FOR KITEAI PROMPT CONFIRMATION LOOP
Replit Implementation Instructions
Last Updated: 2025-12-26

OBJECTIVE
Permanently eliminate the infinite confirmation / recap loop in KiteAI prompt discussions.
Once a user confirms that a workflow should be created, execution must happen exactly once, immediately, and the conversation must terminate.

This is a state machine bug, not a prompt quality issue.

==================================================
SECTION 1 — ROOT CAUSE SUMMARY
==================================================
The AI reaches an “execution-ready” state but user confirmation is treated as conversational input instead of an execution signal.
As a result, the system re-enters summarization and confirmation logic repeatedly.

The fix requires a hard execution latch in application state.

==================================================
SECTION 2 — ADD EXECUTION LATCH TO AI STATE
==================================================

File: client/src/ai/kiteaiState.ts

Add the following fields to the KiteAI state:

hasUserConfirmedExecution: boolean
executionTriggered: boolean

Initial values when conversation starts:
hasUserConfirmedExecution = false
executionTriggered = false

Rules:
• executionTriggered is a one-way latch
• Once executionTriggered === true, it must NEVER revert
• No clarification, recap, or follow-up logic may run after this

==================================================
SECTION 3 — CONFIRMATION INTENT OVERRIDE
==================================================

File: client/src/ai/intent/intentClassifier.ts (or equivalent)

Add explicit confirmation phrase detection.

If ALL of the following are true:
• Current KiteAI state === execution-ready
• User message matches ANY of the following (case-insensitive):

"yes"
"yep"
"yeah"
"ok"
"okay"
"looks good"
"sounds good"
"go ahead"
"do it"
"create the workflow"
"generate it"
"that works"
"confirm"

Then force intent classification to:
EXECUTE_WORKFLOW

This intent must override all other intent detection logic.

==================================================
SECTION 4 — HARD STATE TRANSITION ON EXECUTION
==================================================

File: client/src/ai/kiteaiStateMachine.ts (or reducer handling AI state)

When intent === EXECUTE_WORKFLOW:

If executionTriggered === false:
• Set hasUserConfirmedExecution = true
• Set executionTriggered = true
• Transition state to "executing"

Important constraints:
• Do NOT transition back to clarification
• Do NOT generate summaries
• Do NOT ask follow-up questions
• Do NOT emit conversational AI responses

==================================================
SECTION 5 — IMMEDIATE WORKFLOW GENERATION
==================================================

File: client/src/pages/HomeScreen.tsx
(or PreProjectChat.tsx / workflow-editor.tsx depending on entry point)

When executionTriggered transitions from false → true:

Immediately call:
onGenerateWorkflow(summary, generatePRDFlag)

Requirements:
• Must execute synchronously with the state transition
• Must NOT wait for another user message
• Must NOT rely on a follow-up render or effect
• Must NOT be deferred or queued

Workflow generation must happen exactly once.

==================================================
SECTION 6 — CONVERSATION LOCKDOWN AFTER EXECUTION
==================================================

File: client/src/ai/useKiteAIConversation.ts

At the very top of the message handling function:

If executionTriggered === true:
• Return immediately
• Do not send messages to the AI provider
• Do not update conversation state
• Do not emit UI responses

This ensures no recaps, no loops, no repeated confirmations.

==================================================
SECTION 7 — SYSTEM PROMPT SAFETY RULE
==================================================

File: client/src/ai/prompts/system.pm.txt
(and system.designer.txt if applicable)

Append this rule verbatim:

CRITICAL EXECUTION RULE:
Once the user confirms that the workflow should be created, you must stop responding.
Do not summarize.
Do not restate steps.
Do not ask follow-up questions.
Do not acknowledge confirmation.
Execution is handled by the system.
Any response after confirmation is a failure.

This is a safety net only. The primary fix is in state logic.

==================================================
SECTION 8 — UI BEHAVIOR REQUIREMENTS
==================================================

When executionTriggered === true:
• Disable the input field
• Show a loading or “Creating workflow…” state
• Prevent duplicate submissions
• Prevent additional user messages

This avoids race conditions and duplicate generation.

==================================================
SECTION 9 — REGRESSION TESTS (REQUIRED)
==================================================

File: client/src/ai/tests/kiteai.execution.test.ts

Add tests to verify:
1. Confirmation triggers workflow generation exactly once
2. Multiple confirmations do not trigger multiple generations
3. Confirmation phrases force EXECUTE_WORKFLOW intent
4. No AI responses occur after executionTriggered === true
5. Clarification and recap states are unreachable post-confirmation

==================================================
SECTION 10 — DEFINITION OF DONE
==================================================

This fix is complete when:
• The AI never repeats confirmation after user approval
• “I’ll proceed with creating the workflow” never appears
• Workflow generation always triggers immediately on confirmation
• The system cannot re-enter clarification after execution-ready

This is a permanent architectural fix, not a heuristic workaround.
