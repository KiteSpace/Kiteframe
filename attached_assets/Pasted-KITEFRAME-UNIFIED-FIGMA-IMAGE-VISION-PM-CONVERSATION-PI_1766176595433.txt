KITEFRAME — UNIFIED FIGMA + IMAGE VISION → PM CONVERSATION PIPELINE
EXECUTION INSTRUCTIONS FOR REPLIT
===============================================================

GOAL
----
Unify Figma uploads, image uploads, and text prompts under ONE KiteAI
conversation pipeline with:
• Vision support
• Actionability scoring
• Confidence gating
• Clarification / escalation / execution-ready states

Eliminate the current split behavior where:
• Figma says “cannot analyze external attachments”
• Image uploads bypass PM-style clarification logic
• Vision analysis is treated as a one-shot response instead of conversational input


---------------------------------------------------------------
SECTION 1 — ROOT PROBLEM TO FIX
---------------------------------------------------------------

1. Vision analysis results (image + Figma) are NOT being injected into the
   main KiteAI conversation context.
2. Vision flows bypass:
   • computeActionability()
   • confidence gating
   • clarification / escalation states
3. Figma analysis output is underspecified, so the agent doesn’t know what
   procedural step to take next.

This causes:
• Incorrect “cannot analyze external attachments” responses
• Inconsistent PM reasoning
• Premature “Start project” CTAs


---------------------------------------------------------------
SECTION 2 — REQUIRED ARCHITECTURAL CHANGE
---------------------------------------------------------------

ALL ENTRY MODES MUST FEED THE SAME PIPELINE:

Text Prompt
Image Upload
Figma Upload
↓
[Unified Conversation Context]
↓
Actionability Scoring
↓
Confidence Gating
↓
Clarification / Escalation / Execution-Ready


---------------------------------------------------------------
SECTION 3 — CONVERSATION CONTEXT EXTENSION (REQUIRED)
---------------------------------------------------------------

Add a canonical `sources[]` array to the KiteAI conversation context.

Location:
client/src/ai/kiteaiState.ts (or equivalent shared context)

Add:

interface ConversationSource {
  type: 'text' | 'image' | 'figma-frame'
  payload: any
  confidence: number
  extractedSignals?: Record<string, any>
}

Extend conversation context:

conversationContext.sources: ConversationSource[]


---------------------------------------------------------------
SECTION 4 — IMAGE UPLOAD BEHAVIOR (REQUIRED)
---------------------------------------------------------------

When user uploads an image:

1. Render preview thumbnail (already implemented)
2. Send image to vision pipeline
3. Parse result into STRUCTURED OUTPUT (not prose-only):

Example required structure:

{
  confidence: number,
  signals: {
    screensDetected?: string[],
    flowsDetected?: boolean,
    decisionPoints?: string[],
    missingInfo?: string[]
  }
}

4. Inject result into conversationContext.sources as:
{
  type: 'image',
  payload: imageReference,
  confidence,
  extractedSignals
}

5. DO NOT respond yet.


---------------------------------------------------------------
SECTION 5 — FIGMA UPLOAD BEHAVIOR (REQUIRED)
---------------------------------------------------------------

When user pastes a Figma URL:

1. Authenticate and fetch frame(s)
2. Render preview thumbnails (already implemented)
3. On frame selection:
   • Render frame(s) to image
   • Send image(s) to SAME vision pipeline as image upload

4. Vision output MUST be structured:

{
  confidence: number,
  signals: {
    screenType?: string,
    entryPoints?: string[],
    primaryCTA?: string,
    branching?: boolean,
    missingInfo?: string[]
  }
}

5. Inject into conversationContext.sources as:
{
  type: 'figma-frame',
  payload: {
    frameId,
    frameName,
    image
  },
  confidence,
  extractedSignals
}

IMPORTANT:
Remove any system prompt language that claims:
“I cannot analyze external attachments”


---------------------------------------------------------------
SECTION 6 — ACTIONABILITY & CONFIDENCE PIPELINE (MANDATORY)
---------------------------------------------------------------

After ANY source is added (text, image, figma):

1. Call computeActionability() using:
   • User text
   • Vision extractedSignals
   • Existing conversation context

2. Apply existing thresholds:
   < 0.4 → HARD BLOCK
   0.4–0.7 → CLARIFICATION
   0.7–0.85 → ASSUMPTION PROPOSAL
   ≥ 0.85 → EXECUTION-READY

3. Vision sources MUST NOT bypass this logic.


---------------------------------------------------------------
SECTION 7 — REQUIRED CONVERSATIONAL OUTPUT BEHAVIOR
---------------------------------------------------------------

When confidence < execution-ready:

KiteAI MUST:
• Summarize what it sees (from vision/text)
• Explicitly state what is missing
• Ask targeted PM-style questions

Example:
“I can see this is a linear onboarding flow, but I don’t see any failure
states or role-based branching yet. Before I generate a workflow, I need
to confirm…”

When execution-ready:
• Show “Start project”
• Show “Generate first draft PRD” checkbox
• Allow “Keep brainstorming”


---------------------------------------------------------------
SECTION 8 — REMOVE SPECIAL-CASE BEHAVIOR
---------------------------------------------------------------

Delete or disable:
• Any Figma-only analysis path
• Any image-only shortcut that skips PM reasoning
• Any hardcoded “external attachment” messaging

There must be exactly ONE pipeline.
