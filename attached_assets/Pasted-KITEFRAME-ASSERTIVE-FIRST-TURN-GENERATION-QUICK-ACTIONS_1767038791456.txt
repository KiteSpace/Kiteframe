5.2 How quick actions are determined
After generation, if diagnostics include LINEAR_ONLY or NO_FAILURE_PATH, show:

Map only the happy path -> HAPPY_PATH_ONLY

Include edge / fail cases -> INCLUDE_EDGE_CASES

Discuss edge / fail cases -> DISCUSS_EDGE_CASES

If diagnostics are clean, show no quick actions.

5.3 Behavior for each action

A) HAPPY_PATH_ONLY

Do not change the workflow.

AI responds with a short confirmation: “Keeping this as a straightforward happy path.”

Preview/Create remain available.

B) INCLUDE_EDGE_CASES

Trigger a SECOND AI call: “expand this workflow with common edge/failure cases”

Use the existing graph as context (send nodes/edges) and request an expanded graph.

Normalize the result with normalizeWorkflowGraph.

Re-run analyzeWorkflowDiagnostics.

Update preview.

C) DISCUSS_EDGE_CASES

Do NOT generate a new workflow immediately.

AI responds with a short list of candidate edge/failure cases (max 6) phrased as checkboxes in the UI.

Then show quick actions:

Stick with the happy path -> HAPPY_PATH_ONLY

Map all edge / fail cases -> INCLUDE_EDGE_CASES

Select which edge / fail cases -> SELECT_EDGE_CASES

D) SELECT_EDGE_CASES

Show a small checkbox form with the proposed cases + “Select All”

On submit, trigger an AI call: “expand workflow including ONLY selected cases”

Normalize + update preview.

IMPORTANT: At all times, Preview + Create Workflow must remain available once a baseline workflow exists.
