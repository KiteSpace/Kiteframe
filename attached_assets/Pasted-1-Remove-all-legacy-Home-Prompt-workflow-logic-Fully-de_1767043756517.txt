1. Remove all legacy Home Prompt workflow logic
	•	Fully delete all Home Prompt–specific workflow UI, state, and handlers
	•	This includes (but is not limited to):
	•	Any modal, overlay, or draft UI
	•	Any homeWorkflowDraft or similar state
	•	Any quick-action handlers scoped to Home Prompt
	•	After this step, Home Prompt must contain zero workflow-generation logic

Acceptance:
There is no code path where Home Prompt independently owns or renders workflow state.

⸻

2. Make Home Prompt a pure entry point into KiteAI Chat
	•	Submitting the Home Prompt must:
	•	Open the full-screen KiteAI Chat panel
	•	Inject the Home Prompt text as the first user message in chat
	•	No workflow generation may occur outside the chat pipeline

Acceptance:
Home Prompt behaves identically to a user typing the same text directly into KiteAI Chat.

⸻

3. Centralize all workflow state in KiteAI Chat
	•	There must be exactly one currentWorkflowDraft
	•	It must live in KiteAI Chat (or its shared context)
	•	All workflow generation and mutation must replace this draft
	•	Chat messages may reference workflows, but never own workflow state

Acceptance:
Preview and Create Workflow always operate on currentWorkflowDraft, never on message-local data.

⸻

4. Use a single, unified workflow rendering system
	•	Workflow rendering must be driven solely by currentWorkflowDraft
	•	Preview and Create Workflow buttons render whenever currentWorkflowDraft !== null
	•	The same WorkflowDraftActions component must be used for:
	•	baseline workflow generation
	•	edge/fail case expansion
	•	selected edge case expansion
	•	No UI behavior may depend on message index, message ID, or “first response”

Acceptance:
Buttons re-render automatically whenever the draft changes.

⸻

5. Fix edge/fail case expansion to mutate the workflow draft
	•	“Include edge / fail cases” must:
	•	Call the AI with the existing currentWorkflowDraft
	•	Receive expanded nodes/edges
	•	Replace currentWorkflowDraft with the expanded version
	•	Expansion must not be represented as chat-only text

Acceptance:
After expansion, Preview and Create Workflow operate on the expanded graph.

⸻

6. Guarantee full parity between Home Prompt and KiteAI Chat
	•	The same prompt entered via:
	•	Home Prompt
	•	KiteAI Chat
must produce:
	•	the same baseline workflow
	•	the same quick actions
	•	the same expansion behavior
	•	There must be no conditional logic treating “home-initiated” workflows differently

Acceptance:
Behavior is indistinguishable across entry points.

⸻

7. Manually verify the full end-to-end flow
	•	Home Prompt → chat → baseline workflow
	•	Expand edge/fail cases
	•	Preview reflects expansion
	•	Create Workflow creates expanded version
	•	Repeat entire flow inside KiteAI Chat
	•	Confirm identical results

Acceptance:
All steps behave identically in both paths.

⸻

NON-NEGOTIABLE INVARIANT (DO NOT VIOLATE)

Home Prompt is only an entry point.
All workflow intelligence, state, rendering, and actions live in KiteAI Chat and shared components it owns.
