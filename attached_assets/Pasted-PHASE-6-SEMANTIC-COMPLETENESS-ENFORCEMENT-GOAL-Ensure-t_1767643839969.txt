PHASE 6 — SEMANTIC COMPLETENESS ENFORCEMENT
GOAL:
Ensure that when AI-generated workflows describe stateful behavior
(retries, thresholds, repeated failure, escalation, time-based logic),
the workflow graph STRUCTURALLY encodes that behavior.

This phase MUST NOT:
- Auto-modify workflows silently
- Introduce new node types without feature flags
- Change existing Phase 4 or Phase 5 behavior
- Block all generation by default

This phase SHOULD:
- Detect mismatches between described behavior and structure
- Surface warnings/errors deterministically
- Be auditable and explainable
- Be incrementally enabled

========================================================
PHASE 6A — SEMANTIC CLAIM EXTRACTION (READ-ONLY)
(NO ENFORCEMENT, NO BLOCKING)
========================================================

Task 6A.1 — Define Semantic Claim Types

Create a new file:
client/src/ai/semantic/semanticClaims.ts

Define explicit claim types:

export type SemanticClaimType =
  | 'repeated_failure'
  | 'retry_with_limit'
  | 'threshold_escalation'
  | 'time_based_escalation'
  | 'quota_limit'
  | 'manual_intervention_required';

export interface SemanticClaim {
  type: SemanticClaimType;
  sourceNodeId?: string;
  confidence: number; // 0–1
  evidenceText: string;
}

NO logic yet — types only.

--------------------------------------------------------

Task 6A.2 — Extract Semantic Claims from Generated Content

Create:
client/src/ai/semantic/extractSemanticClaims.ts

Responsibilities:
- Accept workflow nodes + node descriptions
- Scan ONLY node text and insight text
- Detect phrases like:
  - "multiple times"
  - "repeatedly"
  - "after X attempts"
  - "eventually"
  - "threshold"
  - "escalate"
  - "manual review"
- Return SemanticClaim[] with confidence scores

Rules:
- DO NOT infer thresholds
- DO NOT modify workflow
- DO NOT block anything
- Be conservative (false negatives preferred over false positives)

--------------------------------------------------------

client/src/ai/explainability/decisionCapture.ts

Add:

Populate this field during:
- Proposal generation

PHASE 6B — STRUCTURAL EXPECTATION MAPPING (READ-ONLY)
(NO BLOCKING)
========================================================

Task 6B.1 — Define Structural Expectations per Claim

Create:
client/src/ai/semantic/structuralExpectations.ts

Example mapping:

repeated_failure =>
  expects:
    - decision node evaluating count OR state
    - escalation path OR terminal node

retry_with_limit =>
  expects:
    - loop or re-entry edge
    - decision node with exit condition

time_based_escalation =>
  expects:
    - process node indicating monitoring
    - conditional branch for delay exceeded

IMPORTANT:
- These are EXPECTATIONS, not requirements
- No node types added yet
- No enforcement yet

--------------------------------------------------------

Task 6B.2 — Structural Introspection Utility

Create:
client/src/ai/semantic/analyzeStructure.ts

Responsibilities:
- Accept nodes + edges
- Detect:
  - presence of condition nodes
  - presence of terminal/escalation nodes
  - loops or re-entry paths
- Return a StructuralSignature object:
  {
    hasDecisionNodes: boolean;
    hasLoops: boolean;
    hasTerminalEscalation: boolean;
    hasMonitoringStep: boolean;
  }

NO validation logic yet.
