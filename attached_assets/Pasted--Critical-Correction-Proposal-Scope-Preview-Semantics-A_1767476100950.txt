🔒 Critical Correction — Proposal Scope & Preview Semantics (Authoritative)
This Section Overrides Any Prior “Whole Workflow” Interpretation
Core Rule (Non-Negotiable)

“Propose Solution” is scoped to a specific Insight and MUST preview only the affected portion of the workflow.

The preview must not render the full workflow.

1. Proposal Scope Definition

Each Proposal is anchored to a single Insight.

When generating a proposal, the system MUST receive:

insightId

affectedNodeIds[] (minimum: one origin node)

Read-only snapshot of the full workflow for context only

The proposal output MUST include:

New nodes and edges only

No duplication of unrelated existing nodes

Clear attachment points to existing nodes

2. Preview Composition Rules (Very Important)
The preview canvas MUST render:

✅ Existing origin node(s)
✅ Only the proposed new nodes and edges
❌ NOT the full workflow
❌ NOT unrelated existing nodes

Composition Logic (Required)

When building preview data:

previewNodes = [
  ...existingNodes.filter(n => affectedNodeIds.includes(n.id)),
  ...proposedNodes
];

previewEdges = [
  ...existingEdges.filter(e =>
    affectedNodeIds.includes(e.source) ||
    affectedNodeIds.includes(e.target)
  ),
  ...proposedEdges
];


This ensures:

The user sees what exists

The user sees what would be added

The user does not see unrelated structure

3. Preview Canvas Behavior

The preview canvas:

Uses KiteFrameCanvas

Is instantiated separately from the main canvas

Uses:

readOnly={true}


Allows pan & zoom

Disables all editing

Renders only previewNodes / previewEdges

4. Visual & UX Implications (Intentional)

This design communicates:

“Here is the change I’m proposing”

Not: “Here is a replacement workflow”

The user evaluates impact, not architecture

This is intentional and required.

5. Accept / Cancel (Phase 1 Reminder)
Phase 1 Only:

❌ No Accept yet

✅ Cancel clears proposal state

When Accept is implemented later:

Only proposed nodes/edges are merged into the main workflow

Existing nodes are never duplicated or replaced

Undo entry should reflect:

“Apply proposal from Insight: {title}”

6. Explicitly Disallowed Behaviors

Replit must not:

Generate a full alternative workflow

Replace existing nodes

Re-render the entire graph

Implicitly “fix” multiple Insights at once

Assume global authorship transfer

If any of the above feels easier to implement — stop and ask.

7. Validation Checklist (Must Pass)

 Preview shows existing origin node(s)

 Preview shows only newly proposed additions

 Preview omits unrelated workflow regions

 Cancel leaves main canvas unchanged

 No history entries created

 No node ID collisions
