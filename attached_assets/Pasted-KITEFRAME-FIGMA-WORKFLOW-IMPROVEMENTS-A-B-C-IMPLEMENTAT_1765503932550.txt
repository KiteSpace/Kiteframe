SECTION C — SINGLE-FRAME STATE SPLITTING
------------------------------------------------------------
Goal: When a single Figma frame contains multiple logical UI states (e.g., multiple modals, before/after tables, multiple map overlays), generate more than a trivial 3-step flow. We will do this with heuristics FIRST and only optionally lean on AI.

C1. DESIGN PRINCIPLES
---------------------
- KEEP IT SAFE: If heuristics are unsure, fall back to the existing simple workflow so we never hallucinate wildly incorrect flows.
- NO NEW API CALLS TO FIGMA: Use the semantic metadata we already extracted.
- LEVERAGE EXISTING semantic.elements AND forms: Don’t invent a new structure.

C2. HEURISTIC: DETECT MULTI-STATE FRAMES
----------------------------------------
Add a helper in semanticWorkflowGenerator.ts (or a new module it imports) to decide if a frame “looks like” it contains multiple states.

  function inferStateClustersFromSemantic(semantic: FigmaSemanticMetadata): {
    clusters: { id: string; label: string; elementIds: string[] }[];
  } {
    const elements = semantic.elements ?? [];
    const forms = semantic.forms ?? [];
    const clusters: { id: string; label: string; elementIds: string[] }[] = [];

    // Heuristic 1: multiple distinct forms
    if (forms.length > 1) {
      forms.forEach((form, index) => {
        clusters.push({
          id: `form-${index + 1}`,
          label: form.name || `Form state ${index + 1}`,
          elementIds: [...form.fieldIds, ...form.submitButtonIds],
        });
      });
    }

    // Heuristic 2: multiple sets of section-like containers
    const sectionElements = elements.filter(e => e.type === 'section');
    if (sectionElements.length > 1) {
      sectionElements.forEach((section, index) => {
        clusters.push({
          id: `section-${index + 1}`,
          label: section.name || `Section ${index + 1}`,
          elementIds: [section.id],
        });
      });
    }

    // Heuristic 3: navigation targets pointing to different inferredTargetName
    const navTargets = semantic.navigationTargets ?? [];
    const navGroupsByTarget = new Map<string, string[]>();
    for (const target of navTargets) {
      if (!target.inferredTargetName) continue;
      const key = target.inferredTargetName;
      const arr = navGroupsByTarget.get(key) ?? [];
      arr.push(target.elementId);
      navGroupsByTarget.set(key, arr);
    }
    if (navGroupsByTarget.size > 1) {
      let idx = 1;
      for (const [name, elementIds] of navGroupsByTarget.entries()) {
        clusters.push({
          id: `nav-${idx}`,
          label: `State: ${name}`,
          elementIds,
        });
        idx += 1;
      }
    }

    // Optional de-duplication: if two clusters share > 70% of elementIds, keep only one.

    return { clusters };
  }

C3. USE STATE CLUSTERS IN DETAILED WORKFLOW GENERATION
------------------------------------------------------
In semanticWorkflowGenerator.ts, when building the “detailed workflow” steps, do:

  const { clusters } = inferStateClustersFromSemantic(semantic);

  if (clusters.length > 1) {
    logSemanticDebug('WorkflowGenerator multi-state heuristic triggered', {
      clusterCount: clusters.length,
      clusters: clusters.map(c => ({
        id: c.id,
        label: c.label,
        elementCount: c.elementIds.length,
      })),
    });

    const steps: DetailedWorkflowStep[] = clusters.map((cluster, index) => ({
      id: `state-${index + 1}`,
      label: cluster.label || `State ${index + 1}`,
      type: 'user',
      sourceElementIds: cluster.elementIds,
    }));

    const edges: DetailedWorkflowEdge[] = [];
    for (let i = 0; i < steps.length - 1; i++) {
      edges.push({
        sourceStepId: steps[i].id,
        targetStepId: steps[i + 1].id,
        reason: 'inferred-sequence',
      });
    }

    detailedWorkflow = { steps, edges };
  } else {
    // FALL BACK TO EXISTING LOGIC
  }

C4. SAFETY + FALLBACKS
----------------------
- If semantic.elements is empty or missing → skip clustering, use existing logic.
- If clusters.length === 0 → use existing logic.
- If clusters.length is extremely large (> 8) → cap at 8 clusters and log truncation, or fall back to simple chain.
- Never throw an error because clustering failed; just log and continue with the current behavior.
