KITEFRAME — AI USAGE METRICS (BETA)
CHARTS + VISUALIZATION IMPLEMENTATION SPEC
========================================

GOAL
----
Implement an industry-standard AI usage metrics page for Beta users.
• Beta users have unlimited usage
• Usage is tracked for visibility, learning, and future pricing decisions
• NO pricing, limits, or enforcement in this phase

========================================

Filters (left → right):

• Time Range (required)

  - Last 7 days
  - Last 30 days
  - Last 90 days
  - Custom (date picker)

• Feature (multi-select)
  - Chat
  - Workflow Generation
  - PRD Generation
  - Vision Analysis
  - Image Upload
  - Project Summary

• Model
  - All
  - GPT-4o
  - GPT-5.1

• Checkbox:
  [ ] Vision usage only

Filter changes must re-fetch aggregated data.

7. DETAILED USAGE TABLE (BOTTOM)
========================================

Purpose:
Auditability and debugging for power users

Columns:
| Date | Feature | Model | Units | Project | Workflow |

Behavior:
• Paginated (25 rows per page)
• Sortable by:
  - Date
  - Units
• Clicking a row:
  - Focuses related project/workflow

Optional Expand Row (Beta / Debug only):
• Prompt token count
• Completion token count
• Vision multiplier applied


========================================
8. VISUAL STYLE GUIDELINES
========================================

Design language:
• Minimal
• Neutral grayscale
• Color only for differentiation

Colors:
• Muted palette
• Vision usage: subtle accent (purple/indigo)
• No warnings or red states (Beta = unlimited)

Typography:
• Same as PRD / panel typography
• Numeric values use tabular lining


========================================
9. EMPTY STATES
========================================

No data:
"No AI usage yet.
Start by generating a workflow or chatting with KiteAI."

Beta messaging (subtle):
"Unlimited AI usage during Beta.
Metrics shown for transparency."


========================================
10. PERFORMANCE & DATA REQUIREMENTS
========================================

• Use aggregated endpoints ONLY for charts
• Do not load raw events unless table is visible
• Cache aggregates per user + time bucket
• Re-fetch only on filter changes


========================================
11. ACCEPTANCE CRITERIA
========================================

Implementation is complete when:
• Charts render quickly for typical beta usage
• Filters update charts correctly
• Feature/model breakdowns match raw data
• UI feels comparable to OpenAI / Stripe dashboards
• No pricing or limit messaging exists
