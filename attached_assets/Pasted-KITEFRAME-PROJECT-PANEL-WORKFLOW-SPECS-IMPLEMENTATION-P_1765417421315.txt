KITEFRAME – PROJECT PANEL + WORKFLOW SPECS IMPLEMENTATION PLAN
==============================================================

HIGH-LEVEL GOAL
---------------
Replace the existing floating Layers panel with a permanent, right-side "Project Panel"
that contains tabs for:

1) Layers (current layers functionality, but docked)
2) Specs (AI-generated + editable requirements per workflow)
3) Notes (freeform text per workflow or per project)
4) Sources (Figma/Jira/Docs imports)
5) Project Details (high-level metadata)

AND:

- Allow users to generate / regenerate a "Requirements Spec" for a workflow
- Store specs with staleness tracking when the underlying workflow changes
- Provide clear UX for "Spec is out of date → update?"

Do NOT break existing workflow editing, nodes, or Figma import behavior.

1.1 Extend Project / Workflow Metadata
--------------------------------------
There is an existing "ProjectMetadata" and "Workflow groups" concept.
We need to add spec and notes metadata per WORKFLOW (group of nodes + edges),
NOT per node.

In client/src/lib/kiteframe/types.ts (or equivalent):

// Identify the type that represents a workflow group in the Layers panel.
// Example placeholder: adjust to actual name used in codebase.
export interface WorkflowGroup {
  id: string;              // existing
  name: string;            // existing
  nodeIds: string[];       // existing
  edgeIds: string[];       // existing
  // ... existing fields

  // NEW fields for specs & notes:
  spec?: WorkflowSpec | null;
  specStatus?: WorkflowSpecStatus;    // 'none' | 'fresh' | 'stale'
  specLastUpdatedAt?: string | null;  // ISO timestamp
  specLastWorkflowHash?: string | null; // hash string of nodes/edges when spec last updated

  notes?: string | null;             // Freeform markdown / rich-text (plain string for now)
}

// Spec status enum-like type:
export type WorkflowSpecStatus = 'none' | 'fresh' | 'stale';

// Spec structure:
export interface WorkflowSpec {
  id: string;                     // unique id for the spec (uuid)
  workflowId: string;             // reference to WorkflowGroup.id
  title: string;                  // Human-readable spec title (usually workflow name)
  summary: string;                // Short overview paragraph
  sections: WorkflowSpecSection[]; // Structured sections
  createdAt: string;              // ISO timestamp
  updatedAt: string;              // ISO timestamp
  source: 'ai' | 'manual' | 'mixed';

  // Optional: raw markdown / serialized doc for easier round-trips.
  rawContent?: string;
}

// Section type – flexible enough for AI + manual editing
export interface WorkflowSpecSection {
  id: string;
  title: string;                    // e.g. "Overview", "Steps", "Edge Cases"
  content: string;                  // markdown / rich text serialized as string
  // Optional: types or tags for future filtering
  kind?: 'overview' | 'steps' | 'actors' | 'validation' | 'acceptance' | 'open_questions' | 'custom';
}

1.2 Workflow Hashing Helper
---------------------------
We need a stable way to detect when a workflow changed.

Create a helper function (e.g. in client/src/lib/kiteframe/workflowHash.ts):

export function computeWorkflowHash(nodes: Node[], edges: Edge[]): string {
  // 1) Filter to nodes/edges belonging to the workflow (callers pass already-filtered arrays OR full arrays + workflow.nodeIds/edgeIds)
  // 2) Build a minimal representation (id, type, position, label, connections, etc.)
  // 3) JSON.stringify it
  // 4) Compute a simple hash (e.g. murmurhash, or a deterministic hash function; if no lib, use a basic string hash)

  // Important: keep implementation deterministic and stable over time.
}

The hash is stored in WorkflowGroup.specLastWorkflowHash each time we successfully (re)generate or manually save a spec.

1.3 Project Store Extensions
----------------------------
In client/src/lib/store/projectStore.ts (or similar global project/workflow store):

Add actions:

- setWorkflowSpec(workflowId: string, spec: WorkflowSpec, workflowHash: string)
  - Sets group.spec = spec
  - group.specStatus = 'fresh'
  - group.specLastUpdatedAt = now
  - group.specLastWorkflowHash = workflowHash

- markWorkflowSpecStale(workflowId: string)
  - If spec exists, set specStatus = 'stale'

- updateWorkflowNotes(workflowId: string, notes: string)
  - group.notes = notes

Also, inside any node/edge mutation actions (add/remove/rename node, update label, change edge):
- After the operation, recompute the workflow’s hash.
- If it differs from specLastWorkflowHash, mark specStatus = 'stale' for that workflow.

IMPORTANT:
- Do NOT block edits if hashing fails; just log a warning.
- Hashing can be done per workflow group (only nodes/edges that belong to that group for performance).

4.3 Spec Generation Flow (Frontend)
-----------------------------------
In SpecsTab:

When user clicks "Generate Requirements Spec":

1) Get selected workflow from store (id, name, nodeIds, edgeIds).
2) Get project’s nodes + edges arrays.
3) Filter nodes/edges to those belonging to workflow.
4) Compute workflowHash = computeWorkflowHash(filteredNodes, filteredEdges).
5) Call generateWorkflowSpecFromNodes({ projectId, workflow, nodes: filteredNodes, edges: filteredEdges, figmaSemanticData, mode: 'create' }).
6) On success:
   - Call setWorkflowSpec(workflow.id, spec, workflowHash).
7) Handle errors:
   - Show toast "Failed to generate spec. Try again later."

When user clicks "Update Spec" for stale workflow:

- Same steps but mode: 'update' and pass existingSpec: workflow.spec.
- After success, specStatus should be set to 'fresh' and specLastWorkflowHash updated.

When user manually edits spec and hits "Save":

- Update spec fields locally and call setWorkflowSpec(workflow.id, updatedSpec, currentWorkflowHash).
- If there were no workflow changes since last hash, spec remains 'fresh'. If there were changes, spec remains 'stale' until AI update is run (this is acceptable for MVP).

9. STALENESS BEHAVIOR (DETAIL)
--------------------------------------------------

9.1 When to mark spec as stale
------------------------------
In projectStore (or equivalent):

Any of these should mark spec stale if spec exists and specStatus === 'fresh':

- Node added/removed in workflow
- Node type changed
- Node label/title changed
- Edge added/removed
- Edge source/target changed

Implementation:

- After each mutation, recompute workflowHash.
- If workflow.specLastWorkflowHash && workflow.specLastWorkflowHash !== newHash:
  - workflow.specStatus = 'stale'

9.2 When to mark spec as fresh
------------------------------
- After successful AI generation or manual save explicitly triggered as “Accept as current”:
  - setWorkflowSpec(..., workflowHash) which sets specStatus = 'fresh'.

9.3 When no spec exists
-----------------------
- specStatus should be 'none' or undefined.
- No staleness indicator needed.

9.4 UI representation
---------------------
- In SpecsTab header, show a small pill:
  - 'No spec' (gray)
  - 'Up to date' (green / subtle)
  - 'Needs refresh' (orange/red)

- In LayersTab, optionally show a tiny badge next to workflow name:
  - e.g., dot in gray/green/orange to reflect specStatus.
  - This is optional but nice for discoverability.
