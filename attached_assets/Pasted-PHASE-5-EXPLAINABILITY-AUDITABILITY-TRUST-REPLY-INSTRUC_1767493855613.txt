PHASE 5 — EXPLAINABILITY, AUDITABILITY & TRUST
REPLY INSTRUCTIONS (AUTHORITATIVE)

⸻

PHASE 5 GOAL (NON-NEGOTIABLE)

Make Kiteline’s decisions understandable, auditable, and defensible to:
	•	Advanced users
	•	Teams
	•	Enterprises
	•	Regulated environments

WITHOUT changing:
	•	Core UX flows
	•	Interaction mechanics
	•	Proposal / Experiment contracts
	•	Intelligence heuristics from Phase 4

Phase 5 is about legibility and accountability, not smarter generation.

⸻

CORE PRINCIPLE

If Phase 4 made the system smarter,
Phase 5 makes the system trustworthy.

Trust comes from:
	•	Being able to answer “why”
	•	Being able to trace “what happened”
	•	Being able to undo, inspect, and justify decisions

⸻

LOCKED CONSTRAINTS (STILL APPLY)

All constraints from Phases 1–4 remain in force, including:
	•	Insight-scoped actions only
	•	Surgical additions (origin + additions only)
	•	Deterministic previews
	•	Cached generation
	•	Accept / Cancel semantics
	•	Undo atomicity
	•	Container-chrome-only distinction

Phase 5 may add information, but must not alter behavior.

⸻

PHASE 5 SCOPE — ALLOWED ADDITIONS

You MAY add:
	•	Explanatory metadata
	•	Read-only inspection surfaces
	•	Provenance tracking
	•	Decision reasoning summaries
	•	Exportable audit data

You MAY NOT add:
	•	New action buttons
	•	New decision modes
	•	New proposal logic
	•	New AI behavior
	•	Required user interactions

All Phase 5 features must be optional, inspectable, and non-blocking.

⸻

TASK 1 — PROPOSAL & EXPERIMENT PROVENANCE

Goal: Preserve why something exists.

Extend node metadata to include:
	•	createdFromInsightId
	•	createdFromProposalId (if applicable)
	•	createdFromExperimentId (if applicable)
	•	createdAt (timestamp)

Rules:
	•	Metadata must be immutable after creation
	•	Metadata must survive undo / redo
	•	Metadata must survive save / reload

⸻

TASK 2 — DECISION REASONING SNAPSHOT

Goal: Capture the system’s reasoning at decision time.

For each accepted Proposal or Experiment, store a reasoning snapshot:
	•	Insight type(s) involved
	•	Heuristics applied (from Phase 4)
	•	Scope calibration rules applied
	•	Whether this was:
	•	Proposed
	•	Alternative
	•	Experiment
	•	User choice (accepted / rejected)

This snapshot is:
	•	Read-only
	•	Stored alongside the workflow
	•	Never regenerated or recomputed

⸻

TASK 3 — READ-ONLY “WHY” INSPECTOR

Goal: Allow users to inspect decisions without cluttering the UI.

Add a read-only inspector surface that can be opened from:
	•	A node
	•	A workflow history entry
	•	(Later) an audit panel

Inspector shows:
	•	“This node was added because…”
	•	Linked Insight
	•	Proposal / Experiment context
	•	Heuristics that influenced it

Rules:
	•	Inspector must not change state
	•	Inspector must not introduce new actions
	•	Inspector must be dismissible

⸻

TASK 4 — WORKFLOW CHANGE TIMELINE (STRUCTURAL)

Goal: Make evolution visible.

Introduce a structural timeline (not a visual timeline yet) that tracks:
	•	Accept Proposal
	•	Accept Experiment
	•	Undo / Redo events

Each entry records:
	•	Timestamp
	•	Action type
	•	Related Insight
	•	Nodes added

This timeline is:
	•	Internal data first
	•	UI exposure optional and minimal

⸻

TASK 5 — EXPORTABLE AUDIT DATA

Goal: Enable enterprise & regulated use cases.

Provide a way to export:
	•	Workflow structure
	•	Node provenance metadata
	•	Decision reasoning snapshots
	•	Change timeline

Export formats:
	•	JSON (required)
	•	CSV (optional later)

Rules:
	•	Export is read-only
	•	No sensitive prompt data included
	•	No model-specific internals exposed

⸻

TASK 6 — FAILURE & UNCERTAINTY DISCLOSURE

Goal: Be honest when the system is unsure.

If a proposal or experiment was generated under:
	•	Reduced confidence
	•	Heavy sanitization
	•	Conflicting heuristics

Record:
	•	uncertaintyLevel: low | medium | high
	•	validationWarnings (if any)

These are:
	•	Stored in metadata
	•	Visible in inspector
	•	Not shown proactively unless inspected

⸻

TASK 7 — ENTERPRISE SAFETY GUARDRAILS

Goal: Support enterprise roll-out later without refactor.

Add hooks (no UI yet) for:
	•	Disabling AI actions entirely
	•	Read-only mode for workflows
	•	Audit-only access

These are configuration-level switches only.

⸻

EXPLICITLY OUT OF SCOPE (DO NOT IMPLEMENT)
	•	Visual timelines
	•	Inline explanations in the canvas
	•	Tooltips everywhere
	•	AI self-justifications in prose
	•	User-editable reasoning
	•	Automatic compliance checks

Phase 5 is about availability of truth, not verbosity.

⸻

PHASE 5 VALIDATION CHECKLIST

Phase 5 is complete only if:
	•	Every AI-added node can answer “why do I exist?”
	•	Decisions are traceable back to Insights
	•	Undo / redo preserves provenance
	•	Exports reflect real history accurately
	•	No new UX friction introduced
	•	Phase 1–4 guarantees remain intact

⸻

FINAL INSTRUCTION

Phase 5 should make the system defensible in a design review, audit, or post-mortem.

If a stakeholder asks:
“Why is this here?”
The system must be able to answer — calmly, precisely, and truthfully.

⸻

END OF PHASE 5 INSTRUCTIONS
