2. Two Subtle Things to Watch (Important but Small)

These are not blockers, just things to be explicit about during implementation.

Watchpoint 1 — Claim Confidence Must Be Explainable

When blocking is enabled, every blocked case must be explainable in plain language.

Make sure:

confidence is not a magic number

WhyInspector can say why confidence is high:

phrase matched

location (node description vs insight)

repetition

If a user asks “why is this blocking?”, the answer must not be “because the AI said so.”

Watchpoint 2 — Enforcement Must Never Trigger on Descriptions Alone

Blocking should only occur when:

A semantic claim exists and

A structural expectation is missing and

Confidence is high and

Claim type is in the enforced set

Never block simply because:

A description contains “eventually”

A user is brainstorming

A node has speculative text

This keeps Phase 6 from becoming “Phase 4 with teeth.”
