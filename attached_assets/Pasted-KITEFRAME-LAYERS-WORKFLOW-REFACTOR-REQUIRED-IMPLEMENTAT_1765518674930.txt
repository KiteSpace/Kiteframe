KITEFRAME — LAYERS WORKFLOW REFACTOR (REQUIRED IMPLEMENTATION)

GOAL
Refactor the Layers panel so it represents meaningful workflows instead of raw graph artifacts.
This is a structural + UX correctness change, NOT a visual redesign.

A “workflow” must represent a real process, not a single node or debugging artifact.

---

SECTION 0 — DEFINITIONS (DO NOT DEVIATE)

Workflow:
- A connected component with **≥ 2 internal edges**
- Represents a real multi-step process

Standalone Node:
- Any node that does NOT belong to a workflow
- Includes isolated nodes or components with < 2 internal edges

Edges:
- Used for grouping, PRD generation, and AI context
- MUST NOT be rendered in the Layers UI

Decision Node:
- node.type === 'condition'
- Or any node with >1 outgoing edge

---

SECTION 1 — CHANGE WORKFLOW GROUPING LOGIC (CRITICAL)

FILE:
client/src/components/layers/multiViewBuilder.ts

CURRENT BEHAVIOR (WRONG):
- Any connected component = workflow
- Single-node or single-edge components become workflows

REQUIRED CHANGE:
1. After graphWorker returns connected components:
   - Count internal edges per component
2. Only treat a component as a workflow IF:
   internalEdgeCount >= 2

3. If internalEdgeCount < 2:
   - DO NOT create a workflow group
   - Treat all nodes in that component as standalone nodes

IMPLEMENTATION NOTE:
You already have access to:
- nodes
- edges
- component nodeIds

Example logic:

const internalEdges = edges.filter(e =>
  nodeIds.includes(e.source) &&
  nodeIds.includes(e.target)
);

if (internalEdges.length < 2) {
  // add nodes to standalone bucket
  continue;
}

SECTION 4 — HYBRID DECISION TREE VISUALIZATION

GOAL:
Improve readability for non-linear workflows without rendering a graph.

FILES:
client/src/components/layers/TreeRow.tsx
(optional helper in same folder)

REQUIRED BEHAVIOR:
- Render workflows as a linear list
- Detect branching using existing data:
  - node.type === 'condition'
  - OR outgoingEdgeCount > 1

- Indent child rows to indicate branches

Example visual structure:

Workflow: Handling Duplicates
  User submits form
  Decision: Duplicate exists?
    ↳ Yes → Merge records
    ↳ No → Create new record
  System confirms result

IMPLEMENTATION NOTES:
- outgoingEdgeCount is computable from edges prop
- No new data model needed
- No canvas changes required
- Do NOT attempt to render a full graph

Indentation-only is sufficient for v1.
