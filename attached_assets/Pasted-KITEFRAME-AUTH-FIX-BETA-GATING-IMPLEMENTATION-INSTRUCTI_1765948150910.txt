KITEFRAME — AUTH FIX & BETA GATING IMPLEMENTATION INSTRUCTIONS
=============================================================

PURPOSE
-------
Fix broken OAuth login behavior, prevent invalid auth attempts, and harden
the Beta gating flow so non-Beta users cannot access the app while still
allowing waitlist signup.

This document reflects CONFIRMED findings in the codebase.

-------------------------------------------------------------
SECTION 1 — ROOT CAUSE (DO NOT SKIP)
-------------------------------------------------------------

ISSUE:
Google and GitHub OAuth routes are FAILING because their client credentials
are NOT configured in Replit Secrets.

The backend only registers OAuth strategies if BOTH client ID and secret
exist. Since these are missing, the routes are never mounted.

CURRENT STATE:
- Replit OAuth → WORKS (REPL_ID injected automatically)
- Google OAuth → BROKEN (strategy not registered)
- GitHub OAuth → BROKEN (strategy not registered)

The UI still renders Google/GitHub login buttons, causing users to click
routes that do not exist.

-------------------------------------------------------------
SECTION 2 — REQUIRED IMMEDIATE FIX (UI GATING)
-------------------------------------------------------------

GOAL:
Only show auth providers that are actually enabled on the backend.

IMPLEMENTATION:

1. Expose provider availability to the frontend
-----------------------------------------------

Backend (server startup, any file where env is loaded):

Add a provider availability object:

const AUTH_PROVIDERS = {
  google: Boolean(process.env.GOOGLE_CLIENT_ID && process.env.GOOGLE_CLIENT_SECRET),
  github: Boolean(process.env.GITHUB_CLIENT_ID && process.env.GITHUB_CLIENT_SECRET),
  replit: true
};

Export this via:
- an /api/auth/providers endpoint OR
- inject into initial HTML config

Example response:
{
  "google": false,
  "github": false,
  "replit": true
}

2. Gate login buttons in the UI
-------------------------------

In the Login / Landing / Auth component:

- ONLY render a provider button if that provider is enabled.
- NEVER render Google/GitHub buttons if their credentials are missing.

Example logic:

if (providers.google) show Google button
if (providers.github) show GitHub button
always show Replit button

This prevents users from triggering dead auth routes.

-------------------------------------------------------------
SECTION 5 — BETA GATING (CONFIRMED CORRECT, DO NOT MOVE)
-------------------------------------------------------------

Current behavior (KEEP THIS):

1. OAuth authentication completes
2. User record is created / loaded
3. Beta gate runs AFTER auth
4. Routing:
   - isBeta === true → /app
   - isBeta === false → /waitlist-dashboard

This is the correct model:
- OAuth = identity
- Beta flag = authorization

Do NOT block OAuth itself for non-Beta users.

  - "Sign in" → only allowed if provider enabled

If a non-Beta user authenticates:
- Redirect to waitlist dashboard
- DO NOT allow access to Home / Editor
