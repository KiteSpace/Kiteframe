- Nodes are inserted as reference frames
- Users may later generate workflows from selected frames

----------------------------------------------------------------------

----------------------------------------------------------------------

client/src/components/modals/FigmaImportModal.tsx

    → Allow:
        [Select All] [Select None] [Checkbox selection per frame]

The modal should return ONLY selected frames to the caller.

----------------------------------------------------------------------
2. Extend Metadata on Imported Image Nodes
----------------------------------------------------------------------
Modify:
convertFigmaFrameToNodes()  
convertMultipleFramesToNodes()

For each imported frame node, ADD:

data: {
    ...existing,
    figmaFileKey,
    figmaNodeId: frame.id,
    figmaNodeName: frame.name,
    isReferenceFrame: true,
    sourceType: "figma-frame",

SECTION 2 — LAYERS PANEL PROJECT-SCOPING (BUG FIX)
----------------------------------------------------------------------

### GOAL
Fix cross-project contamination where layers, collapsed states, workflow names, and workflow groups leak between projects.

### REQUIRED FIXES

----------------------------------------------------------------------
1. VERIFY all stores are project-scoped
----------------------------------------------------------------------
Fix the following so they include projectId:

collapseStore  
visibilityStore  
lockStore  
workflowNameStore  
nodeToWorkflowStore  

KEY NAMESPACE:
kiteframe-layers-[projectId]-collapse  
kiteframe-layers-[projectId]-visibility  
kiteframe-layers-[projectId]-workflowNames  
kiteframe-layers-[projectId]-nodeToWorkflow  

----------------------------------------------------------------------
2. Add resetLayersState(projectId)
----------------------------------------------------------------------
File:
layersStateManager.ts (or equivalent store module)

Implement:

export function resetLayersState(projectId: string) {
    collapseStore.reset(projectId);
    visibilityStore.reset(projectId);
    lockStore.reset(projectId);
    workflowNameStore.reset(projectId);
    nodeToWorkflowStore.reset(projectId);
}

----------------------------------------------------------------------
3. Call resetLayersState() any time projectId changes
----------------------------------------------------------------------
Modify:
workflow-editor.tsx (or page wrapper)

When a new project loads:

useEffect(() => {
    resetLayersState(projectId);
}, [projectId]);

SECTION 3 — WORKFLOW GENERATOR IMPROVEMENTS
----------------------------------------------------------------------

### GOAL
Improve generated workflows from Figma semantic data.

### REQUIRED CHANGES

----------------------------------------------------------------------
1. DO NOT auto-generate workflows during import
----------------------------------------------------------------------
Only trigger workflow generation when the user clicks:

“Generate Workflow”

----------------------------------------------------------------------
2. Add “Generate Workflow from Selected Frames” Flow
----------------------------------------------------------------------
Modify:
LinearToolbar OR Action Button Handler

When clicking Generate Workflow:
- If >1 reference frames exist:
    Show small popover:
        ( ) Generate from All Frames  
        ( ) Select Frames…

If “Select Frames” → Show quick picker.

----------------------------------------------------------------------
3. Generate Workflow in ONE Workflow Group
----------------------------------------------------------------------
Modify:
semanticWorkflowGenerator.ts

Ensure:
- All generated nodes belong to SAME workflow group
- Use rootFrameNode.position as base offset for positioning

----------------------------------------------------------------------
4. Node Creation: Preserve Clean Labels
----------------------------------------------------------------------
Avoid meaningless labels such as:
"Node 12345"

Instead:
Use semantic element name:
Button → “CTA: Sign In”  
Input → “Field: Email”  
Section → “Section: Header”

----------------------------------------------------------------------
5. Edge Creation
----------------------------------------------------------------------
Use figmaSemantic.workflowGraph.edges to construct edges:

edges.push({
    id: uuid(),
    source: stepIdMap[source],
    target: stepIdMap[target],
    label: reason ?? ''
})

----------------------------------------------------------------------
6. Undo System Integration
----------------------------------------------------------------------
Wrap all node+edge creation inside a single undo batch:

undoManager.batch(() => {
    // add nodes
    // add edges
}, "Generate Workflow");

----------------------------------------------------------------------
7. Final Layout
----------------------------------------------------------------------
Use LayoutPlugin:

core.layout.verticalFlow(newNodes, { spacing: 120 });
