## SECTION 1 — WORKFLOW GROUPING & DATA MODEL

1. Does the current codebase already compute connected components of nodes/edges?
   - If yes, what function calculates this?
   - If no, should we add a grouping utility or integrate it into editor state?

2. When Figma imports generate new workflows, does each imported frame already map to isolated node groups?
   - If not, do we need to enforce workflow isolation?

3. Are nodes stored with "workflowId" today, or do we need to add this field as metadata?

4. Can each workflow be uniquely identified across sessions (persistent ID)?
   - If not, should workflowId be derived from root node ID?

## SECTION 2 — SEMANTIC HASHING

5. Does a semantic hashing utility already exist in the codebase?
   - If yes, what fields are included/excluded?
   - If no, where should we insert a new hashing module?

6. Node position (x,y), dimensions, and style must be excluded from the hash.
   - Any side effects of ignoring these fields?

7. Should workflow hash run automatically on:
   - node add?
   - node remove?
   - edge add/remove?
   - node label/data change?

8. Where is the best place in the codebase to store “previous workflow hash”
   so we can detect “stale vs fresh” PRD states?
