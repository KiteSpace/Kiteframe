KITEFRAME — HOME TAB PROMPT & FILE UPLOAD UX SPEC
FINAL REPLIT HANDOFF (TXT)

SCOPE
-----
This work ONLY affects the Home tab (pre-project experience).
NO changes to:
- Workflow editor
- Canvas
- Project tabs
- Layers panel
- Existing project chat
- Node generation logic

Home tab behaves like Figma’s Home:
- Start ideas
- Upload references
- Clarify intent
- Create project ONLY when user confirms

--------------------------------------------------
1. HIGH-LEVEL UX STATES (MANDATORY)
--------------------------------------------------

The Home tab has exactly THREE states:

STATE A — ENTRY VIEW (DEFAULT)
STATE B — FULL-SCREEN PRE-PROJECT CHAT
STATE C — PROJECT CREATION (EXIT HOME)

No other states are allowed.

--------------------------------------------------
2. STATE A — ENTRY VIEW (HOME DEFAULT)
--------------------------------------------------

Location:
client/src/components/HomeScreen.tsx

UI REQUIREMENTS:
- Full-width vibrant gradient background (top section only)
- Opaque white card centered in hero area
- Headline + short explanation
- Prompt textarea
- Upload buttons:
  - Figma
  - Image
  - Document
- Primary CTA: “Start designing”
- Recent Projects list BELOW the hero

IMPORTANT:
- No project exists yet
- No canvas
- No workflow generation here

--------------------------------------------------
3. USER ACTION HANDLING (STATE A)
--------------------------------------------------

A1. USER TYPES A PROMPT + CLICKS “START DESIGNING”

Send prompt to /api/ai/chat with INTENT CLASSIFICATION prompt.

AI MUST RETURN:
{
  intentConfidence: "high" | "medium" | "low",
  clarifyingQuestions: string[],
  summary: string
}

BEHAVIOR:
- If intentConfidence === "high" AND clarifyingQuestions is empty:
  → Show “Create project” CTA
  → DO NOT open chat
- Otherwise:
  → Transition to STATE B (chat)

--------------------------------------------------

A2. USER UPLOADS FILE (FIGMA / IMAGE / DOCUMENT)

RULE:
Uploads NEVER auto-create a project.

Behavior:
- Parse/summarize file
- Send summary to /api/ai/chat
- ALWAYS transition to STATE B (chat)

Reason:
File intent is ambiguous by default.

--------------------------------------------------
4. STATE B — FULL-SCREEN PRE-PROJECT CHAT
--------------------------------------------------

Purpose:
Resolve ambiguity BEFORE project creation.

UI REQUIREMENTS:
- Full-screen gradient background
- Large opaque white chat card
- Back / Cancel button at top-left
- Chat history visible
- Bottom input bar with:
  - Text input
  - Attachments
  - Send button

IMPORTANT:
- No project yet
- No canvas
- No workflow generation

--------------------------------------------------
5. CHAT BEHAVIOR RULES (STATE B)
--------------------------------------------------

AI ROLE:
Act as a Product + Systems Designer.

AI SHOULD:
- Ask scoped clarifying questions
- Summarize understanding
- Avoid generating workflows yet

AI RESPONSE TYPES:
1. Clarifying question(s)
2. Intent summary + missing info
3. “Ready to create project” signal

ONLY when AI signals readiness:
- Show “Create project” CTA

--------------------------------------------------
6. EXITING CHAT / PROJECT CREATION (STATE C)
--------------------------------------------------

Project is created ONLY when:
- AI indicates readiness
- User explicitly clicks “Create project”

Implementation:
Call createNewTab() from workflow-editor.tsx

Allowed:
- Empty project
- OR project with generated nodes (if already resolved)

NOT allowed:
- Auto-create on upload
- Auto-create on chat completion
- Auto-create without user confirmation

--------------------------------------------------
7. BACK / CANCEL BEHAVIOR
--------------------------------------------------

Back button in chat:
- Returns to ENTRY VIEW
- Discards pre-project chat state
- No project created

--------------------------------------------------
8. STATE MANAGEMENT
--------------------------------------------------

HomeScreen local state only.

Add:
- homeMode: 'entry' | 'chat'
- preProjectChatMessages: Message[]
- preProjectContext: {
    prompt?: string
    uploadedFiles?: File[]
    aiSummary?: string
  }

DO NOT reuse project chat state.

--------------------------------------------------
9. API USAGE
--------------------------------------------------

Reuse:
POST /api/ai/chat

No new endpoints required.

Add a SYSTEM PROMPT for intent classification:
- Ask AI to decide:
  - Is this actionable?
  - What info is missing?
  - Should a project be created now?

--------------------------------------------------
10. NON-NEGOTIABLE GUARDRAILS
--------------------------------------------------

DO NOT:
- Create projects on upload
- Generate workflows in Home tab
- Enter chat unless intent is unclear
- Modify project pages

DO:
- Require explicit “Create project”
- Keep Home tab pre-project only
- Match Figma Home vs File behavior

--------------------------------------------------
11. ACCEPTANCE CRITERIA
--------------------------------------------------

- Clear prompt → Direct project creation
- Vague prompt → Chat
- Any upload → Chat
- Chat always requires confirmation
- Back button never creates project
- Project pages remain unchanged

END OF SPEC
