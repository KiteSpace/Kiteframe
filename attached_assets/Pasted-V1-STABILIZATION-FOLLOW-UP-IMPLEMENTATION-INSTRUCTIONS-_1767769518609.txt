=======================================================
PHASE A — SESSION LOCKING (MANDATORY, DO FIRST)
=======================================================

GOAL
----
Ensure deterministic AI behavior within a single workflow session.
Once a proposal/experiment session begins, the model + provider must NOT change
until the session ends (Accept, Cancel, or page refresh).

LOCKED CONSTRAINTS
------------------
- No UX changes
- No user-facing indicators
- No blocking behavior
- Client-side only (session-scoped)
- Applies ONLY to workflow_reasoning and workflow_experiments task types

IMPLEMENTATION TASKS
--------------------

A1. Create Session Lock Utility
- File: client/src/ai/router/sessionLock.ts
- Implement a session-scoped lock using sessionStorage

Data shape:
interface SessionModelLock {
  provider: string;
  model: string;
  lockedAt: number;
}

Rules:
- First router call with a sessionId creates the lock
- Subsequent calls with same sessionId MUST reuse locked model/provider
- Ignore localStorage / settings changes during active session

A2. Integrate Lock into AI Router
- File: client/src/ai/router/aiRouter.ts
- Before resolving model selection:
  - If taskType is workflow_reasoning OR workflow_experiments
  - AND a sessionId is provided
  → Apply session lock

A3. Wire sessionId into Callers
- Files:
  - workflow-editor.tsx
  - generateProposedWorkflow.ts
  - generateExperiments.ts
- Generate a stable sessionId at:
  - Propose Solution start
  - Experiment generation start
- Pass sessionId through ALL router.chat() calls in that flow

A4. Enforce Determinism
- Proposed + Alternative MUST use same model
- All experiments in a batch MUST use same model
- Regeneration must reuse locked model

ACCEPTANCE CRITERIA
-------------------
[ ] Model does NOT change mid-session
[ ] Changing settings during proposal has no effect until session ends
[ ] Cancel clears session lock
[ ] Accept clears session lock
[ ] Page refresh clears session lock
[ ] No UX changes observed

----
Detect potential infinite or pathological loops
WITHOUT blocking or modifying workflows.

This is observational only for V1.

------------------

- Feature-flagged
- No auto-repair
- No blocking
- No new nodes or edges
- No Test Flight failures caused by this phase

IMPLEMENTATION TASKS
--------------------

C1. Loop Detection Utility
- File: client/src/ai/analysis/loopDetection.ts
Detect:
- Cycles without exit nodes
- Retry loops without counters or escalation
- Self-referencing decisions without terminal paths

C2. Feature Flag
- Flag name: ENABLE_LOOP_DETECTION_WARNINGS

C3. Integrate with Test Flight

ACCEPTANCE CRITERIA
-------------------
[ ] Loop warnings are informational only
[ ] No workflow is blocked
[ ] No auto-repair occurs
[ ] Warnings appear in inspector + audit export
[ ] Feature flag can fully disable behavior
