1) QA ACCEPTANCE CHECKLIST (V1 ChatGPT-Style Chat)

Use this checklist verbatim during QA. All items must pass for V1 sign-off.

A. Visual & Layout

 No avatars appear anywhere (user, assistant, system).

 User messages render as subtle, right-aligned bubbles.

 Assistant messages render as paragraph-style prose (no bubble, no background).

 System messages are visually distinct (italic, muted), not bubbles.

 Workflow proposal cards remain visually distinct and are not wrapped in bubbles.

 Fullscreen chat is centered with a max-width; panel chat uses the same typography and spacing, just narrower.

B. Typography & Readability

 Assistant text has comfortable line length (~60–75ch).

 Line height ~1.5–1.6 for assistant prose.

 Clear paragraph spacing; no cramped blocks.

 Lists render with proper indentation and spacing.

 Code blocks have breathing room and horizontal scroll if needed.

C. Message Grouping

 Consecutive assistant messages are grouped (reduced vertical spacing).

 Increased spacing occurs only when roles change.

 Grouping does not change message order or content.

D. Scroll Behavior

 Chat auto-scrolls only if user is already near the bottom.

 When user scrolls up, new messages do not jump the viewport.

 A “↓ New message” indicator appears when messages arrive off-screen.

 Sending a user message forces scroll to bottom.

 Behavior matches ChatGPT (no scroll hijacking).

E. Input Composer

 Textarea auto-resizes up to max height.

 Enter submits; Shift+Enter inserts newline.

 Input disables during loading.

 Focus returns to input after send.

F. Persistence & State

 Chat history persists across reloads.

 No schema changes to ChatMessage.

 No regressions in proposal accept/reject flows.

G. Non-Goals (Confirm Not Implemented)

 No avatars added.

 No reactions/edit/regenerate controls.

 No token-by-token streaming UI (unless explicitly approved).

PASS CRITERION:
If all boxes above are checked, chat meets V1 acceptance for launch.
